## 技术栈

| 项 | 选择 | 说明 |
| --- | --- | --- |
| 前端 | React 19 + TypeScript + Vite | 一套代码出网页端与（将来的）桌面端 |
| 编辑器 | **BlockNote**（ProseMirror 内核） | 斜杠菜单、拖拽手柄、块菜单开箱即用（对应手册候选池 A 的首选） |
| 本地数据库 | **Dexie / IndexedDB**（Apache-2.0） | 有索引、事务、**版本化迁移**；存储层隔离在 `data/db.ts`，将来要落成真正的 `.sqlite` 文件只改这一层 |
| 图标 | Iconify **离线**多套（Lucide / MingCute / Phosphor / Tabler） | 可整套切换（M8-09）；只打包用到的图标 |
| 状态 | zustand | 文档数据在库里，store 只是内存镜像；界面偏好走 localStorage（要秒开，不能等异步读库） |
| 桌面壳 | Tauri 2（**已接入**，Windows 桌面与 Web 共用本套代码） | 体积/内存优于 Electron，原生窗口/更新能力已用上 |

## 常用命令

```bash
npm install          # 首次
npm run dev          # 开发服务器（默认 http://localhost:5173）
npm run build        # 生产构建
npm run test         # 数据层回归测试（vitest + fake-indexeddb）
npm run check        # 图标映射校验 + 类型检查
npm run check:icons  # 只校验图标映射
```

> `predev` / `prebuild` 会自动跑 `tools/gen-icons.mjs`：**只把我们用到的图标打进产物**。
> 直接 import 图标库整包会让产物从 1.2MB 涨到 12MB——这个坑已经踩过，别再犯。

## 踩过的坑（别再犯）

1. **`orderBy` 的字段必须有索引**。`listPages` 用了 `orderBy("sortKey")` 但 v1 建库时没给 `sortKey` 建索引，
   Dexie 直接抛 SchemaError——表现是**永远停在"正在打开知识库…"**。
   → 已补 v2 索引；同步加了"启动失败要显示错误"的路径。
2. **启动流程必须有失败路径**。上面那个 bug 之所以难查，是因为界面只是静静转圈，没有任何提示。
   现在 `store.hydrate` 有 catch，失败会显示原因和"重新载入"按钮。
3. **不要 import 图标库整包**。四套库全量打进去会让产物从 1.2MB 涨到 12MB。
   一律走 `tools/gen-icons.mjs`（已挂在 predev/prebuild）。
4. **图标名打错不会报错**，只会渲染空白。所以有 `tools/check-icons.mjs` 逐条对着图标库原始数据校验。
5. **注释里别出现 `*/`**。写 `@iconify-json/*/icons.json` 这种路径会把块注释提前结束，构建直接失败。
6. **新页面的标题不要设成字面量 `"无标题"`**，否则用户点进去打字会接在它后面（"无标题磷化工笔记"）。
   空标题交给 `placeholder` 显示。
7. **固定宽的侧栏 + 右栏会挤死主区**。574px 视口下主区只剩 26px；窄窗口要让右栏浮起来。
8. **用脚本模拟拖拽时，事件之间要留时间**。`dragstart` 里设的 React 状态是异步生效的，
   紧接着同步发 `dragover`，处理函数里读到的还是"没在拖拽"，会误判成应用有 bug。
   正确做法：`dragstart` → 等 ~250ms → `dragover` → `drop`。
9. **删页面要留退路**。删掉最后一篇时若不管，界面就没东西可开——所以自动补一篇空页。
10. **图片绝不能把 `blob:` 地址写进文档**。blob 地址只在当次打开有效，写进库下次打开全是破图。
    做法：文档里存 `asset://附件id`，显示时换成真地址、写库前换回去（见 `data/assets.ts`）。
    这条对"剪藏图片备份""附件字段"都一样适用。
11. **窄屏的浮层会把正文盖住**。所以 <1000px 时右栏要自动收起——但**不要写进用户偏好**，
    否则用户在宽屏上也会莫名其妙看不到右栏。
12. **"跳转到某一块"不能挂在 React 的 effect 上**。在同一篇页面内点搜索结果时，
    页面 id 没变、正文就绪状态也没变，effect 根本不会重跑 → 表现为"点了没反应"。
    改成由搜索自己带重试地去找元素（见 `data/search.ts` 的 `runPendingFocus`）。
13. **导出/导入的标题会重复**。Markdown 里的 `# 标题` 既会变成页面标题、又留在正文第一块，
    导出时再补一行标题就出现两次。两头都处理：导入时去掉同名首块，导出时检测开头已有标题就不再补。
14. **HMR 的中间态会留一串假报错**。改代码过程中控制台常出现"未导出/未定义"的错误，
    验证前先整页刷新一次，否则很容易把历史报错误判成新 bug（这次就差点）。
15. **自定义块的斜杠菜单项要用 `updateBlock` 而不是 `insertBlocks`**。
    用 insertBlocks 插在下面，光标留在原来的空段落里，用户接着打字会打到块外面去；
    用 updateBlock 把当前块直接变成目标块，光标自然就在里面了。
16. **自定义块导出要有语义结构**。toExternalHTML 用 `<blockquote>` 而不是 `<div>`，
    Markdown 导出才会变成 `> ...` 引用块；用 div 会退化成一行普通文字，语义就丢了。
17. **zustand 选择器不能返回"新造出来的数组/对象"**。
    写成 `useStore(s => s.records[id] ?? [])` 时，每次调用都返回一个新数组，
    React 认为状态一直在变 → 无限重渲染 → **整页白屏**。
    正确写法：先取稳定的那一层（`s.records`），回退值用模块级常量（`EMPTY_RECORDS`）。
    这类 bug 只在运行时炸、类型检查完全看不出来。
