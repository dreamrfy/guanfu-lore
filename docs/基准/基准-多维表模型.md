## 1 三类对象的类型体系（别混）

| 对象 | `type` 的类型 | 实测取值 |
| --- | --- | --- |
| **块**（含数据库块、记录行） | **number** | `0`（页面）、`18`/`19`（数据库） |
| **字段**（列） | **string** | `title` / `text` / `select` / `multi_select` / `date` / `url` / `id_number` / `created_at` |
| **视图** | **string** | `table` / `board` / `timeline` / `calendar` |

> 这是 M0-T08 里那条提醒的落地：**块的 type 是数字，字段与视图的 type 是字符串**，三套别混。

## 2 数据库块（承载表的那个块）

数据库相关信息全在 `block.data` 里：

| 键 | 含义 |
| --- | --- |
| **`schema`** | **字段（列）定义** |
| `collectionPageProperties` | 记录页（行详情页）的属性配置 |
| `collectionProperties` | 集合属性配置 |
| `icon` / `cover` / `coverPos` / `description` | 数据库本身的图标/封面/说明 |
| `format` / `pageFixedWidth` | 格式化 |
| `segments` | 标题的行内文本 |

数据库块同时挂在 `block.views` 上（该页挂载的视图）。视图的完整定义在 `data.collectionViews`。

## 3 字段（列）定义

**字段定义只有三个键**（实测形状分布：`{name, options, type}` ×31、`{name, type}` ×12）：

```
schema: {
  "<字段id>": { name: string, type: string, options?: array }
}
```

- `name` —— 列名
- `type` —— **字符串型**（见下表）
- `options` —— **数组**（选项列表；`select` / `multi_select` 就是在这里存可选项）

### 3.1 实测到的字段类型（8 种）

| type | 出现次数 | 说明 |
| --- | --- | --- |
| `select` | 9 | 单选 |
| `text` | 8 | 文本 |
| `multi_select` | 7 | 多选 |
| `title` | 6 | **标题列**（每表必有） |
| `date` | 6 | 日期 |
| `url` | 3 | 链接 |
| `id_number` | 2 | 自动编号 |
| `created_at` | 2 | 创建时间（系统字段） |

> ⚠️ **这 8 种只是"该用户当前用到的"，不是 FlowUs 支持的全部。**
> FlowUs 还有 `number` / `checkbox` / `member`(人员) / `file`(文件) / `formula`(公式) / `relation`(关联) / `rollup`(汇总) / `updated_at` 等，**本次样本里一个都没有**。
> → 已拆为 **M0-T18**：故意建一张"每种字段类型一列"的测试表，把完整清单与各类型的 `options` 结构采齐（做完删表）。

## 4 记录（行）

**关键发现：记录本身就是「页面块」**——实测 142 条记录的块类型全部是 `number: 0`，且**它们的 `parentId` 指向数据库块**。

```
数据库块(type 18)  ──subNodes──▶  记录行(type 0)  ──▶  有自己的页面（正文 + 属性区）
```

这正好对上产品体验：**「多维表里的每一行 = 一个页面」**（FlowUs 官方叫"记录页/页面版数据库"）。所以 M4-T07「记录页」不是发明，是这套数据模型的必然结果。

记录块里与表格相关的两个键：`collectionProperties`（该行的属性值）、`collectionPageProperties`（记录页的属性展示配置）。

## 5 视图（view）

视图存在 `data.collectionViews`，**以 view uuid 为键**。视图对象字段（实测全量）：

```
uuid, type, title, format, collectionId, parentId, shareId, pageSort,
status, spaceId, version, createdAt, createdBy, updatedAt, updatedBy, deletedBy
```

### 5.1 实测视图类型（4 种）

| type | 出现次数 |
| --- | --- |
| `table` | 10 |
| `board` | 1 |
| `timeline` | 1 |
| `calendar` | 1 |

## 6 给 M4 的实现要求

1. **一个「记录」= 一个页面块（type 0）**，`parentId` 指向数据库块。不要另造"行"实体——否则记录页、属性、正文全都要重做一遍。
2. **字段定义照抄 `{name, type, options}` 三键结构**；`options` 是**数组**（不是对象）。
3. **字段 type / 视图 type 用字符串**，与块的数字 type 分开建表。
4. **视图配置全放 `format`**，键名照抄第 5.2 节（尤其 `filter` / `sorters` / `openPageWay` 是通用项）。
5. **记录行有 `subNodes`**（它自己也是页面，可以带子页面）——树上不显示记录，但数据模型里它在。
