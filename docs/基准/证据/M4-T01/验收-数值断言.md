## 2. 三个刻意的取舍（都写进代码注释）

1. **不另造"行"实体**：记录就是页面块。否则记录页、属性区、正文都要重做一遍（§6 第 1 条）。
2. **单元格值原样持有 map**：`collectionProperties` 的内部结构 M0 还没采齐（摊在后续任务），
   现在自造一套"值类型"就是在编；先原样存，等采到真结构再收紧。
3. **不硬凑标题列**：`titleField` 找不到 `type=title` 的列就返回 `null`，不拿第一列顶替。

16 条断言的落点：

- 19 个字段字符串 → 中文名（逐项）；未知类型保留 `rawType`；系统字段判定（created_at/created_by/updated_at/updated_by/id_number）
- 7 种视图字符串；`format` 里的未知配置项往返不丢；`filter`/`sorters`/`openPageWay`/`pageSort` 可取
- 字段顺序 = schema 键顺序；记录 parentId 指向库块；单元格值（含 `['o1']` 这种数组）原样
- 记录自己也是页面（`subNodes` 保留）；标题列识别；默认视图**优先表格视图**而不是数组第一个
- 序列化往返不变 + **二次序列化与一次逐字节相同**（幂等，不会越存越胖）；空正文/坏 JSON 不抛
