20 条断言的覆盖点：

1. 16 个数字码 → 中文名（逐个比对）
2. 未知码 99 → `unknown`，但 `rawType`/`toJson()['type']` 保留 99
3. 标题级别取 `data.level`
4. `enhancer` 里的未知键往返不丢
5. 块的真实顶层键集（backgroundColor/textColor/status/version/createdAt/updatedAt/spaceId/permissions/isTemplate/templatePages/moved/discussions）往返不丢，`data` 原样
6. 根块 = parentId 为空的页面块
7. 子块顺序按 `subNodes`（故意倒序）
8. 六种旧块 → 正确数字码 + 根块 type=0
9. 分割线无 `segments`、待办保留勾选、标题带 level
10. 纯文本 → 非空行转段落
11. 空正文只有根块（不凭空造空段落）
12. `storedVersionOf` 区分 v2 / v1 / 纯文本 / 坏 JSON
13. 六类块 encode→decode 往返（含勾选与级别）
14. 旧 v1 内容仍能读
15. 空正文 → 一个空段落块
16. 坏 JSON 不崩、文字原样保留
17. `schemaVersion == 8`
18. v1 正文迁移后变 v2 且内容不丢（内存 SQLite 实跑）
19. 迁移幂等（跑两遍字符串不变）
20. 空正文页面迁移后仍是空串

## 4. 如实说明的三处

1. **待办勾选状态的键名未经实测**：真实 FlowUs 把"勾没勾"存在哪个键，M0 没采到。我们暂存
   `data.checked`，并在代码里写明"等 M4/M6 采到真键名再迁移"——不是猜成 FlowUs 的字段。
2. **行内样式在当前编辑器上会丢**：旧 6 类编辑器没有行内样式，v2→BlockData→v2 会丢 `enhancer`。
   今天库里没有任何带样式的页面（旧格式从来没存过），真编辑器（M2-T05）上线后此限制消失。
3. **迁移的"调用路径"靠 drift 触发，测试只覆盖迁移函数本身**：`onUpgrade` 里 `if (from < 8) await
   migrateContentToFlowUsBlocks();` —— 断言直接调用该函数验证数据变换；drift 在真升级时确实会调它，
   但"从 v7 库真实升级到 v8"这条路径没有 schema dump 可回放（drift 的 schema 校验需要 codegen 产物），
   所以没有自动化断言。**这条我标为未验证**，等 M2-T14（保存链与崩溃恢复）有旧库样本时补。
