# M1-T16 字体打包与剩余外观 · 验收记录

日期：2026-11-10　执行者：watchdog 会话

## 1 结论先行：**不需要打包 webfont**

任务原写"字体没打包 → 回退系统字体 → 字更宽更松"。这轮先量后判定，结论被推翻了一半：

**真 FlowUs 的字体栈**（computed `font-family`，与我们 `FlowUsTypography.fontFamily` 完全同序）：

```
my-quote, "PingFang SC", "Microsoft YaHei", ui-sans-serif, -apple-system, BlinkMacSystemFont,
"Segoe UI", Helvetica, Helvetica, "Apple Color Emoji", Arial, sans-serif, "Segoe UI Emoji", "Segoe UI Symbol"
```

**它自己声明的 webfont**（`document.fonts` 全量）：`my-quote`（1 个 face，西文）、
**`LXGW WenKai`（194 个分片）**、`source-han-serif-sc-regular`（194 个分片）。
即：**中日韩字形来自霞鹜文楷 / 思源宋体，是本机 webfont 按需加载**；Windows 上默认栈最终落到 `Microsoft YaHei`——和我们一样。

**像素级核验**（直接从两张对照截图量墨迹宽度，比 widget test 可信——测试环境是 Ahem 等宽字体，会"假绿"）：

| 文本 | 真 FlowUs | 我们 | 差 |
| --- | --- | --- | --- |
| 磷化工知识库 @14/500（6 字） | **83 px** | **83 px** | 0 |
| 空间容量已用完 @14/600（7 字） | **97 px** | **98 px** | +1 |
| 升级后可继续上传 @12/400（8 字） | **96 px** | **96 px** | 0 |

→ **字宽一致**。"我们的字更宽更松"是 **2× 放大对照 + w500 假粗体**造成的观感差：
YaHei 只有 400/700 两档，Flutter 对 `w500` 会合成假粗（墨色更重、看着更大）；Chrome 对 `w500` 直接给 400。

## 2 这轮真正做了的两件

1. **首页按钮的激活态浅灰圆角块**（M1-T13 对照里真 FlowUs 第一格有底、我们没有）
   - `FlowUsShell`/`FlowUsSidebar` 新增 `activeQuickIconIndex`（null = 无激活），演示壳传 0
   - 尺寸 32×32、圆角 6、底色用 `FlowUsColors.sidebarItemSelected`（黑 6%）
   - 断言：有激活时第一格 `BoxDecoration.color == sidebarItemSelected` 且圆角 6，第二格无色
2. **截图工装的右缘黑边**：窗口按 `W+16` 调宽后超出 1920 屏幕右缘 → 把窗口 x 左移到 `−frameW/2`，客户区左缘贴 0，黑边消失。

## 3 老实说没解决的（都是"渲染器差异"，不是配置错）

| 差异 | 原因 | 处置 |
| --- | --- | --- |
| w500 看起来更黑更粗 | Flutter 合成假粗体，YaHei 无 500 字重 | 若以后要更贴，可打包 **LXGW WenKai（OFL 许可，可合法内置）** 作 CJK 主字形，它带 400/500 真字重 |
| 图标的描边/填充视觉重量仍略重 | 我们用的是采到的**填充式** SVG，浏览器端靠 `fill-current` 同样渲染；差异主要在字形栅格 | 记录在案，随字体方案一起复核 |
| 「客服气泡 / W 徽标」 | 本轮在侧栏底部（y > 视口高−140）**没有找到**任何 20–40px 的圆形控件 | 判定：该账号侧栏底部没有此控件（M1-T13 对照时的印象来自窗口截图里的其它应用），不再追 |
| 起笔位置差 3~4px | 字形 side bearing 差（不同字体族） | 与字重一并归到"若上 LXGW WenKai 再复核" |
