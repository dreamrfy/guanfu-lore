## 1 关联 = `relation`（**实测，不是猜的**）

M0-T26 当时点「关联」类型没变（配置层被我 Escape 掉了）。这次**不 Escape**，看清了流程：

```
点「分类」列头 → 更换类型 → 点「关联」
  → 弹出「选择集合」浮层（240×292），列出可关联的表：无标题多维表格×2 / 学习进度 / 微信公众号剪藏 / 网页剪藏
  → 点「学习进度」→ 配置层关闭 → 读接口：该字段 type = "relation"
```

**`relation` 这个 string 是这么测出来的**，不是按 Notion 惯例推的。

## 2 关联字段的完整结构（比名字更有用）

实测 `schema[字段id]` 的键：

```
collectionId, formula, name, options, pairProperty, spaceId, type
```

| 键 | 含义（据字段名与现象推断，**未逐项验证**） |
| --- | --- |
| `collectionId` | **关联到哪张表**（目标集合 id） |
| **`pairProperty`** | **反向字段**（在目标表上配对的字段） |
| `spaceId` | 所属空间 |
| `options` | 选项（select 类字段也有这个键，**结构本轮没采**） |
| `formula` | 公式（关联字段也带这个键） |

**另一个真实样本**：目标表「学习进度」里有一个已有的关联字段 **`同步分类`**，其键为
`collectionId, name, pairProperty, spaceId, type`（**没有 `formula` 和 `options`**）——
说明这两个键是**可选**的。

## 3 ⚠️ 本轮做了一件有副作用风险的事，已核查并如实报告

**关联字段会在目标表上生成反向字段（`pairProperty`）。** 我的测试表的关联指向了「学习进度」，
所以**有可能在 学习进度 上加了字段**。

**核查结果（删掉测试表后重读）：**

| 项 | 值 |
| --- | --- |
| 学习进度 的含 schema 块 | **1 个**（blockType=18） |
| 字段数 | **8 个** |
| 字段清单 | 任务(title) / 状态(select) / **同步分类(relation)** / 类型(select) / 周次(select) / 备注(text) / 年份(select) / 月份(select) |

**判断**：`同步分类` 在**删掉我的测试表后依然存在** → 它是**原有字段**，不是我加的反向字段；
字段数前后都是 **8**、**没有新增**。→ **学习进度的表结构没有被改动**。

**一处需要如实说明的疑点**：两次读取中，第 5 个字段名在我这边的输出里显示不同
（一次显示为"人名占位符"、一次显示为"周次"）。**判断是我这边输出脱敏替换造成的显示差异，不是表被改**——
但我无法 100% 排除。**如果你发现「学习进度」多了或少了字段，请告诉我。**
→ 已写进 M0-T30 作为"复核项"，并且**以后凡涉及关联的采集，一律不要指向用户的真实表**
（可以新建两张隔离表互相关联）。
