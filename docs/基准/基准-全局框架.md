## 1 三段式布局

```
┌──────────┬────────────────────────────────────────────┐
│          │  标签条  h=48                              │  y=0
│  侧栏    ├────────────────────────────────────────────┤
│  228px   │  系统横幅（容量等） h=44                   │  y=48
│ 固定     ├────────────────────────────────────────────┤
│          │                                            │
│          │  主内容区（滚动）                          │  y=92
│          │      ┌──────────────┐                      │
│          │      │ 内容列 708px │ 水平居中             │
│          │      └──────────────┘                      │
└──────────┴────────────────────────────────────────────┘
 x=0        x=228                                     x=视口宽
```

| 区域 | 数值 | 备注 |
| --- | --- | --- |
| 侧栏 | 宽 **228px**（含 1px 右边框 → 内容区 227px） | `position: fixed`，`z-index: 100`，**不随视口变化** |
| 标签条 | 高 **48px**，x 从 **228** 起，宽 = 视口宽 − 228 | 背景 `rgb(255,255,255)`，底边框 1px `rgb(229,229,229)` |
| 系统横幅 | 高 **44px**，紧贴标签条下方（y=48） | 背景 `rgba(2,133,255,0.05)`，底边框 1px `rgba(2,133,255,0.1)` |
| 主内容区 | 起点 **y=92**（= 48 + 44），无横幅时 y=48 | 滚动容器类名 `default next-space-page overflow-y-auto` |
| 内容列 | 固定 **708px**，在主区内水平居中 | 见下 |

> 横幅是**条件出现**的（空间容量已满 / 升级提示等）。没有横幅时主内容区上移到 y=48。**布局必须按"有无横幅"两种状态都对齐。**

## 2 横向布局规则（已跨视口验证）

实测 5 个视口宽度，结论：**侧栏恒 228px，内容列恒 708px**，只有标签条与主内容区跟着视口伸缩。

| 视口宽 | 侧栏 | 标签条 x / 宽 | 内容列 |
| --- | --- | --- | --- |
| 1280 | 228 (+1px 边框) | 228 / 1052 | 708 |
| 1440 | 228 (+1px 边框) | 228 / 1212 | 708 |
| 1600 | 228 (+1px 边框) | 228 / 1372 | 708 |
| 1920 | 228 (+1px 边框) | 228 / 1692 | 708 |
| 2560 | 228 (+1px 边框) | 228 / 2332 | 708 |

**内容列水平居中公式**：
```
内容列 x = 228 + (视口宽 − 228 − 708) / 2
```
验算 1920：`228 + (1920 − 228 − 708) / 2 = 228 + 492 = 720` → 实测内容列 x = **720** ✓

**主区留白 = 居中算出来的，不是固定 padding**（这是最容易做错的地方）：

| 视口宽 | 主区宽 | 内容列左右留白（各侧） |
| --- | --- | --- |
| 1280 | 1052 | **172** |
| 1440 | 1212 | **252** |
| 1600 | 1372 | **332** |
| 1920 | 1692 | **492** |
| 2560 | 2332 | **812** |

→ 实现时必须「主区内居中 + max-width 708」，**不要写死左右 padding**（写死就只在某一个窗口大小下是对的）。

## 3 滚动条

- **overlay 型**：实测文档与全部滚动容器的 `offsetWidth − clientWidth` **均为 0**，即滚动条**不占布局宽度**。
  - 直接影响：**内容列不会因为出现滚动条而横向抖动**；我们实现时不要用占位的经典滚动条。
- 主内容区滚动容器：`x=228, y=92, w=视口宽−228, h=视口高−92`，`overflow-y: auto`。
- 详情见证据 `scrollbars.json`。

## 6 实现注意（给 M1 的硬要求）

1. 侧栏与内容列都是**固定像素**，不要用百分比或弹性宽度；只有标签条/主内容区拉伸。
2. 内容列用「主区内居中 + max-width 708」，而不是在外层容器上加左右 padding —— 否则视口变化时会跑偏。
3. 滚动条必须是 **overlay 不占位**；Windows 上要显式处理（默认可能占 17px）。
4. 系统横幅是**独立一条**，出现时把主内容区整体下推 44px；不要做成浮层遮住内容。
5. 侧栏在窄视口**不要自动收窄**（实测 1280 也是 228px）。
