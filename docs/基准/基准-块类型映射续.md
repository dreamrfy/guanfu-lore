## 3 失败原因分析（三条，按可能性排序）

1. **斜杠菜单的"输入快捷码 + 回车"选择不可靠**：回车选的是**过滤后的第一项**，而过滤可能没命中目标（甚至没打开菜单）。第一次之后，光标停在新块里，`Enter` 未必新建块、`/` 也未必重新唤起菜单。
2. **块被就地转换而不是新建**：差集第一次报 `type=12`、最终却是 `type=25` → 说明**同一个块被反复改写**（我的"新块"判定只能看到新增 uuid，看不到"类型被改"）。
3. **太快**：每步只等 1.2–1.7 秒，虚拟列表与保存可能没跟上。

## 4 下一步（改法，已写进新任务 M0-T28）

**先解决"能不能可靠地造一个指定块"这个问题，再谈映射。** 具体：

1. **先查斜杠菜单项有没有 `data-test-id`** —— M0-T23 的重大教训是"**数据库菜单项有中文名 test-id**"，斜杠菜单很可能也有。**若有，就按 test-id 点击**，彻底绕开"输入+回车选第一项"的不可靠路径。（这一步只需 1 次探测，最该先做。）
2. 若没有 test-id，则**每次造块前先删掉旧块、保证只有一个空块**，并在每次操作后**等 2.5 秒以上**再读接口。
3. **判定要升级**：不能只比 uuid 新增，还要比 **同一 uuid 的 type 是否变化**（本轮就是这里吃了亏）。
4. 每造一个块就截图存证，便于事后核对"界面上到底出现了什么块"。
