## 3 产物：下载文件名规则（实测）

| 格式 | 文件名 |
| --- | --- |
| Markdown & CSV | `<页面标题>+<页面id前8位>.zip` |
| PDF | `<页面标题>.pdf` |
| Word | `<页面标题>+<页面id前8位>.zip`（内含 `.docx`） |

- 标题里的**空格会被替换成 `+`**（实测：`04 29 出发…` → `04+29+出发…`）
- PDF 用**纯标题**，不带 id；压缩包类**带 id 前 8 位**以避重名

## 4 **Markdown & CSV 包的结构（最重要）**

实测：**zip 内的目录结构 = 页面树的镜像**。规则如下：

```
<页面标题>+<页面id>/                      ← 导出根目录
├── <子页面标题>+<页面id>/                 ← 每个页面 = 一个同名目录
│   ├── <页面标题>+<页面id>.md            ← 页面正文导出为 md
│   ├── <多维表标题>+<页面id>/             ← 多维表也是目录
│   │   ├── <表/视图名>+<页面id>.csv      ← ★ 表数据导出为 CSV
│   │   └── <记录标题>+<记录id>/           ← ★ 每条记录 = 一个目录
│   │       ├── <记录正文>.md
│   │       └── <记录的子页面>+<id>/…
│   └── <第三个子页面>+<页面id>/
└── …
```

**三条要点**：
1. **页面 = 目录**；正文导出为**与目录同名的 `.md`**。
2. **多维表 = 目录 + 一个 `.csv`**（表数据），**每条记录是它下面的一个子目录**（可含自己的 `.md` 与子页）——**这与 M0-T09 的发现完全吻合**（记录即页面）。
3. 目录名/文件名一律是 **`标题+id`**，id 是页面/记录的 uuid。

**导出选项的实际影响（实测）**：
- 勾「**导出子页面**」/「**按目录导出**」→ 包内含整棵子树（实测包从 9KB 变 76KB）
- 「**导出附件**」→ 是否把附件文件带进包

> **对 M6 的价值**：这张结构表就是**导出器的实现规格**（M6-T01/T02），也是**导入器的解析依据**（M6-T05）。
> 而且印证了 M0-T08 的判断：**权威数据源其实是 `/api/docs/{id}`**（比 markdown 更完整）；导出包适合"给人看的备份"，**导入优先走接口**。
