## 0 怎么拿到这些值的（重要方法说明）

FlowUs **不用 CSS 变量**——实测整页只有 3 个自定义属性，还都是图标 URL。它的配色是**编译进 Tailwind 工具类**的：`bg-aside`、`text-t2`、`border-grey7`…

所以本表是**从「class 名 → 计算样式」反推**出来的：抓下每个可见元素的 class 与 `getComputedStyle` 值，按 `前缀-名字` 归组（`bg-*` → `background-color`、`text-*` → `color`、`border-*` → `border-color`），取同组出现最多的值。

- 样本：328 个可见元素（`归档历史材料` 页 + 完整外壳）
- 排除项：`text-left` / `text-ellipsis` 这类排版工具类已过滤，不算颜色
- 局限：一个 token 在不同上下文会有变体（多为 hover / 选中态或继承），下文只取**主值**

## 2 语义 token 对照（class → 值）

FlowUs 的命名体系是「语义名 + 灰阶编号」，我们实现时**照抄这套命名**，迁移和对照都会省事。

| token | 值 | 语义 |
| --- | --- | --- |
| `active_color` | `#0285FF` | 主色基色 |
| `bg-active_color` | `rgba(2,133,255,0.05)` | 极浅主色底（系统提示条） |
| `bg-active_color_10` | `rgba(2,133,255,0.10)` | 选中底 |
| `border-active_color` | `rgba(2,133,255,0.30)` | 主色边框（聚焦/选中） |
| `border-active_color_10` | `rgba(2,133,255,0.10)` | 提示条边框 |
| `bg-aside` | `#F7F7F7` | 侧栏底 |
| `bg-white` / `bg-white1` | `#FFFFFF` | 内容底 / 标签条底 |
| `bg-black_006` | `rgba(0,0,0,0.06)` | 悬停底 |
| `grey2` | `#5F5E5B` | 次级文字 |
| `grey3` | `#91918E` | 三级文字 |
| `grey5` | `#E0E0E0` | 重边框 |
| `grey6` | `#E5E5E5` | 默认边框 |
| `grey7` | `#F0F0F0` | 浅边框 / 侧栏右边框 |
| `t2` | `#37352F` | 正文主色 |
| `t2-medium` | `#5F5E5B` | 次级（中粗） |
| `t4` / `t4-medium` | `#91918E` | 三级 |
| `black` / `black2` / `h4` | `#000000` | 标题 / 选中 |

**透明度变体规律**：主色的浅底一律用 **alpha 变体**（0.05 / 0.10 / 0.30），而不是另一个实色。实现时也用 `rgba` 叠加，别用硬编码的浅蓝。这样换主色时一改全改。

## 3 对比度核验（结论：FlowUs 自己有 5 组不达 WCAG AA）

阈值：普通文字 4.5:1。完整表见 `docs/基准/证据/M0-T03/contrast-table.md`。

| 组合 | 对比度 | 判定 |
| --- | --- | --- |
| 正文 `#37352F` on 内容底 / 侧栏底 / 悬停底 / 选中底 | 12.26 / 11.44 / 10.76 / 10.88 | 达标 |
| 次级 `#5F5E5B` on 内容底 / 侧栏底 / 悬停底 / 选中底 | 6.48 / 6.05 / 5.69 / 5.75 | 达标 |
| 黑标题 `#000000` on 内容底 | 21.00 | 达标 |
| **三级 `#91918E` on 内容底** | **3.16** | ❌ 不达标 |
| **三级 `#91918E` on 侧栏底** | **2.95** | ❌ 不达标 |
| **主色 `#0285FF` on 内容底** | **3.62** | ❌ 不达标 |
| **主色 `#0285FF` on 侧栏底** | **3.38** | ❌ 不达标 |
| **白字 on 主色（实心按钮，普通字号）** | **3.62** | ❌ 不达标 |
| 白字 on 主色（大字号按钮 ≥24px） | 3.62 | 达标（大字号阈值 3.0） |

**这 5 项是 `#0285FF` 蓝本身很亮导致的**（蓝色通道饱和、亮度高），不是我们换算错。

### 取舍（需要用户知晓）

用户的硬要求是**「像素级一模一样」**，所以默认做法是**照抄 FlowUs 的值，连这 5 项差距一起抄**。
本项目的旧调色板曾把全部组合压到 ≥4.56，现在按 FlowUs 复刻会**主动退回到不达 AA**。

**建议（等用户一句话）**：
- 默认：**照抄**，保持 1:1；本文档把差距写明，不偷偷改。
- 若用户希望"外观一致但文字更清晰"，最小改动是把三级文字与主色文字**各压深一档**（如主色用 `#0070E0`，三级用 `#7A7A77`），肉眼几乎看不出、AA 可过。**这条等用户拍板，不擅自改。**

## 4 深色主题：**有！而且是跟随系统**（M0-T14 纠正 M0-T03 的错误结论）

### 4.1 先认错

M0-T03 时我下的结论是「该端无深色主题」，**这是错的**。当时的做法是**找一个"手动开关"**：侧栏图标行 5 个入口 / 空间设置全表 / 「更多」菜单 / localStorage / 根节点 `color-scheme` —— 全都没找到，就下了"没有"的结论。

**错在方法**：FlowUs 的深色主题**不是手动开关，而是跟随系统的 `prefers-color-scheme`**。

### 4.2 决定性证据

用 CDP 模拟系统深色偏好（`Emulation.setEmulatedMedia` → `prefers-color-scheme: dark`）后，界面**整体换肤**：

| 探针 | 浅色 | 模拟深色后 |
| --- | --- | --- |
| 侧栏底 | `rgb(247,247,247)` | **`rgb(32,32,32)`** |
| 侧栏右边框 | `rgb(240,240,240)` | **`rgb(46,46,46)`** |
| body 底 | 透明 | **`rgb(25,25,25)`** |
| body 文字 | `rgb(55,53,47)` | **`rgb(212,212,212)`** |

→ **确认存在深色主题，切换条件是系统外观**（不是应用内开关）。

### 4.3 深色板全套（实测，与浅色逐项对照）

| 用途 | 浅色 | **深色** | HEX |
| --- | --- | --- | --- |
| 内容底 | `#FFFFFF` | **`rgb(25,25,25)`** | `#191919` |
| 侧栏底 | `#F7F7F7` | **`rgb(32,32,32)`** | `#202020` |
| 正文主色 | `#37352F` | **`rgb(212,212,212)`** | `#D4D4D4` |
| 次级文字 | `#5F5E5B` | **`rgb(160,160,160)`** | `#A0A0A0` |
| 三级文字 | `#91918E` | **`rgb(113,113,113)`** | `#717171` |
| 「黑」（最强文字） | `#000000` | **`rgb(212,212,212)`** | `#D4D4D4` |
| 默认边框(grey6) | `#E5E5E5` | **`rgb(46,46,46)`** | `#2E2E2E` |
| 侧栏右边框(grey7) | `#F0F0F0` | **`rgb(46,46,46)`** | `#2E2E2E` |
| 重边框(grey5) | `#E0E0E0` | **`rgb(54,54,54)`** | `#363636` |
| **悬停底(black_006)** | `rgba(0,0,0,0.06)` | **`rgba(255,255,255,0.06)`** | ← **白 6%！** |
| 选中底(active_color_10) | `rgba(2,133,255,0.10)` | 同（不变） | — |
| 主色 active_color | `#0285FF` | **不变** | `#0285FF` |

### 4.4 三条实现要点（最容易踩的坑）

1. **色值是成对反转的**：浅色 `#FFFFFF / #F7F7F7 / #E5E5E5` ↔ 深色 `#191919 / #202020 / #2E2E2E`。做主题时按"对"建模，别一个个写死。
2. ⚠️ **`bg-black_006` 这个 token 在深色下是白 6%**：它的语义是**「当前主题的前景色的 6%」**，不是字面黑色。
   → 实现时悬停底必须写成 **`当前前景色 × 6%`**，写死 `rgba(0,0,0,0.06)` 在深色下会完全看不见。
3. ⚠️ **`black` 这个 token 在深色下是 `#D4D4D4`**（浅色下才是 `#000000`）：它的语义是**「最强文字」**，不是字面黑。
   → 命名照抄没问题，但**值必须按主题取**。

### 4.5 深色板对比度核验（比浅色**更接近达标**）

完整表见 `docs/基准/证据/M0-T14/contrast-dark.md`。

| 组合 | 深色对比度 | 浅色对比度 | 判定 |
| --- | --- | --- | --- |
| 正文 on 内容底 / 侧栏底 / 悬停底 / 选中底 | 11.86 / 10.99 / 10.08 / 10.64 | 12.26 / 11.44 / 10.76 / 10.88 | 都达标 |
| 次级 on 内容底 / 侧栏底 | 6.72 / 6.23 | 6.48 / 6.05 | 都达标 |
| **主色文字 on 内容底 / 侧栏底** | **4.86 / 4.50** ✅ | 3.62 / 3.38 ❌ | **深色下反而达标** |
| **三级文字 on 内容底 / 侧栏底** | **3.60 / 3.34** ❌ | 3.16 / 2.95 ❌ | 两边都不达标 |
| **白字压主色（实心按钮）** | **3.62** ❌ | 3.62 ❌ | 两边都不达标 |

**小结**：浅色 **5 项**不达标 → 深色 **3 项**不达标（主色文字在深底上够了）。**"FlowUs 自身不达 AA"这个问题依然存在，只是深色下少两项。**

## 5 给 M1/M8 的实现要求

1. **照抄命名**：直接建 `active_color` / `grey2..grey7` / `t2..t4` 这套 token，别自创名字。
2. **浅底一律 alpha 叠加**（0.05 / 0.10 / 0.30），不要写死浅蓝色值。
3. **默认边框就是 `#E5E5E5`**——实测出现 307 次，这个值用错整页都会"差一点"。
4. 悬停底是**黑 6% 叠加**，不是固定灰；在侧栏（`#F7F7F7`）和内容底（`#FFFFFF`）上合成结果不同，必须叠着算。
5. 深色主题在 **M0-T14 有结论之前不要动手做**，否则必返工。
