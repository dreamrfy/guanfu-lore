# 阶段一部署 · 控制台操作清单（你照着点）

- 配套代码已全部备好：云函数包已打好，在 **`server/out/bijiapp-poll.zip`**（约 11MB）
- 预计用时：30–40 分钟；做完这一轮，手机转发就能自动进知识库
- 原则：**只在控制台点，不碰代码**；任何一步和清单不符，截图给我，不要猜

---

## 第 0 步 · 备好两份凭证（只有你有，约 5 分钟）

**A. 微信客服凭证 5 项**（已在本地文件里，打开照抄即可）
- 文件：`E:\dev\tmp\wecom-secrets\wecom-kf.json`
- 要抄的字段：`corpId` / `agentId` / `appSecret` / `token` / `encodingAESKey`

**B. R2 凭证 4 项**（Cloudflare 控制台，见第 3 步现场拿）
- 如果你之前的项目存过 R2 密钥文件，直接用那份；否则按第 3 步新建

> 凭证只抄到你自己的本地记事本，**不进微信聊天、不进项目文件夹**。

---

## 第 1 步 · 关键确认：Runtime 版本（1 分钟，最重要的一步）

1. 浏览器打开 **tcb.cloud.tencent.com**（CloudBase 控制台）→ 进入环境 **`biji-gcsb`**（上海）
2. 左侧「云函数」→ 点「新建云函数」（先别真的建）
3. 看弹窗里的**「函数代码 → 运行时」下拉**里有哪些 Node 版本，最高到多少
4. **把这个版本清单告诉我**（截图最快）：
   - 有 **Node 24** → 直接用我打的 zip，继续第 2 步
   - 没有 Node 24 → 停在这里告诉我，我改成「预编译 JS」打包方式再给你新 zip

---

## 第 2 步 · 建数据库集合（2 分钟）

CloudBase 控制台 → 左侧「数据库」→「集合管理」：

1. 点「新建集合」，名字填 `clips`（存剪藏记录）
2. 再点「新建集合」，名字填 `poll_state`（存拉取进度）
3. 权限保持默认（「仅创建者可读写」即可——云函数走的是管理员通道，不受此限）

---

## 第 3 步 · Cloudflare 建 R2 桶 + 拿凭证（约 5 分钟）

1. 打开 **dash.cloudflare.com** → 左侧「存储和数据库」→「R2 对象存储」
2. 点「创建存储桶」：名字填 **`bijiapp-assets`**（小写字母和连字符，其他默认）
3. 在 R2「概览」页右侧找到**「账户 ID」**（32 位字母数字）→ 记为 `R2_ACCOUNT_ID`
   ⚠️ 别把「API 令牌」页里 `cfat_` 开头的标识当成账户 ID
4. R2 →「管理 R2 API 令牌」→「创建 API 令牌」：
   - 权限选「**对象读和写**」，作用范围限定桶 `bijiapp-assets`
   - 创建后得到 **Access Key ID** 和 **Secret Access Key**（只显示一次，马上抄下来）
5. 此时你手里应有 4 个值：`R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET`（值就是 `bijiapp-assets`）

---

## 第 4 步 · 建云函数（约 10 分钟）

CloudBase 控制台 →「云函数」→「新建云函数」：

| 项 | 填什么 |
| --- | --- |
| 函数名 | `bijiapp-poll` |
| 运行时 | 第 1 步确认的最高 Node 版本（最好 Node 24） |
| 创建方式 | **上传 ZIP 包** → 选 `E:\VBcoding\bijiapp\server\out\bijiapp-poll.zip` |
| 内存 | 512 MB |
| 超时 | 300 秒 |
| 环境变量 | **9 项**（见下表；键名一字不差，值不加引号、首尾别带空格） |

环境变量对照表：

| 键名 | 值来自 |
| --- | --- |
| `KF_CORP_ID` | 第 0 步 A 的 corpId |
| `KF_AGENT_ID` | 第 0 步 A 的 agentId |
| `KF_APP_SECRET` | 第 0 步 A 的 appSecret |
| `KF_TOKEN` | 第 0 步 A 的 token |
| `KF_ENCODING_AES_KEY` | 第 0 步 A 的 encodingAESKey |
| `R2_ACCOUNT_ID` | 第 3 步的账户 ID（32 位） |
| `R2_ACCESS_KEY_ID` | 第 3 步的 Access Key ID |
| `R2_SECRET_ACCESS_KEY` | 第 3 步的 Secret Access Key |
| `R2_BUCKET` | `bijiapp-assets` |

**部署后立即测试**：进函数详情 →「函数代码」页 → 点「**测试**」按钮 → 测试事件留 `{}` → 运行。

- **正常**：返回一段 JSON 统计（拉取消息 / 游标 / 入库数之类），或 `拉取消息: 0`（新环境没消息，正常）
- **报错**：把返回内容和「日志」里的红字一并截图给我，**不要自己改**

---

## 第 5 步 · 定时触发器（2 分钟）

函数详情 →「触发器」→「创建触发器」→ 选「定时触发器」：

- 触发周期：选「自定义触发周期」，填 `0 */30 * * * * *`（**7 段**，意思是每 30 分钟跑一次）
- 名称：`pollEvery30Min`，状态启用

---

## 第 6 步 · 端到端验收（5 分钟）

1. 手机上往「微信客服」转发一篇公众号文章
2. 回到控制台函数页，点「测试」（不用等 30 分钟）
3. 检查三处：
   - 「测试」返回的 JSON：入库数 +1
   - 数据库 → `clips` 集合：出现新记录，`status` 是 `complete`
   - R2 桶 `bijiapp-assets` → `assets/` 目录下出现对象（`.html` 快照、`.png` 图片）
4. 把结果截图给我：全对 = 阶段一上线完成；有异常 = 我修

## 常见报错对照

| 报错 | 原因 | 处理 |
| --- | --- | --- |
| `凭证环境变量未设置：KF_XXX` | 环境变量漏填或键名打错 | 对照第 4 步表格补齐 |
| `R2_ACCOUNT_ID 应为 32 位…` | 把 API 令牌标识当成了账户 ID | 用概览页右侧的账户 ID |
| `图片主机不在白名单` | 正常安全防护 | 把转发的内容告诉我即可 |
| 返回里有 `errcode` 非 0 | 微信接口侧返回错误 | 把完整返回截图给我 |
