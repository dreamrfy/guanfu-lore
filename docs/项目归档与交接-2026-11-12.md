## 1. 产品是什么

**AI 原生的块式个人知识库**（PKM / 第二大脑）。
闭环 = **捕获（剪藏）→ 整理（多维表格）→ 提炼（AI）→ 输出（导出/分享）**。

三条核心需求（用户原话归纳）：

1. **标准化的笔记编辑器**（格式不限，核心是编辑体验）
2. **互联网信息剪藏**（公众号 / 小红书 / B站 / 抖音；转发或链接；要防原文被删的本地备份）
3. **Agent 级 AI**（可自定义供应商、总结改写、**能自己挂 Skill 与 MCP**）

## 3. 工作纪律（用户定的铁律，必须遵守）

1. **不重复造轮子 / 「一切皆插件」**
   写任何代码前，先查是否已有成熟开源件（GitHub / Gitee / 论坛）。

2. **数据主权**：核心数据自托管（用户 VPS + Cloudflare R2），AI 走云端 API。
3. **验收口径分开写**：「界面/几何完成」与「功能已实装（点下去数据真的变）」**不能混为一谈**——

### 5.4 数据库结构（Dexie v4）

| 表 | 主键 | 索引 | 说明 |
| --- | --- | --- | --- |
| `pages` | id | parentId, updatedAt, deletedAt, sortKey | 页面元信息（含软删字段=回收站） |
| `docs` | pageId | updatedAt | 每篇正文（BlockNote 块数组），与元信息分开存 |
| `meta` | key | — | 键值（预留） |
| `assets` | id | pageId, kind, createdAt | 图片/文件（以 ArrayBuffer + mime 存，不存 Blob） |
| `collections` | id | updatedAt | 多维表格定义（fields / views 内嵌） |
| `records` | id | collectionId, updatedAt | 表格记录（values: fieldId→值） |

## 7. 已知限制与风险（必须让审查 AI 知道）

1. **未提交 git**：`app/` 整个目录还是 untracked；`docs/` 下三份新文档也未提交。
   一旦误删无从恢复——**建议先提交一次**（用户决定，AI 不要擅自提交）。
2. **本地数据库是 IndexedDB，不是 SQLite 文件**：

## 8. 踩过的坑（17 条，接手的人务必先读）

> 这些坑都真实发生过，多数"只在运行时炸、类型检查看不出来"。

1. **`orderBy` 的字段必须有索引**。否则 Dexie 抛 SchemaError，表现为**永远停在"正在打开知识库…"**。
2. **启动流程必须有失败路径**。否则界面只会静静转圈，用户无从下手；现在失败会显示原因 + 重新载入按钮。
3. **图标库不要整包 import**。四套全量打进去产物从 1.2MB 涨到 12MB；用 `tools/gen-icons.mjs` 只打用到的。
4. **图标名打错不会报错，只会渲染空白**。`tools/check-icons.mjs` 逐条校验（曾抓出 `mingcute:table-2`、`tabler:layout-sidebar-left` 两个错误名）。
5. **注释里别出现 `*/`**。写 `@iconify-json/*/icons.json` 这种路径会提前结束块注释，构建直接失败。
6. **新页面标题不要设成字面量 `"无标题"`**，否则用户点进去打字会接在后面（"无标题磷化工笔记"）。空标题交给 placeholder。
7. **固定宽的侧栏 + 右栏会挤死主区**（574px 视口下主区只剩 26px）；窄窗要让右栏浮起来。
8. **用脚本模拟拖拽时事件之间要留时间**。`dragstart` 里设的 React 状态是异步生效的，紧接着发 `dragover` 会读到"没在拖拽"——**容易误判成应用 bug**。
9. **删页面要留退路**。删掉最后一篇时自动补一篇空页，否则界面没东西可开。
10. **图片绝不能把 `blob:` 地址写进文档**。blob 地址只在当次打开有效，写进库下次打开全是破图。文档里存 `asset://附件id`，显示时换、写库前换回。
11. **窄屏浮层会盖住正文**，自动收起可以，但**不能写进用户偏好**。
12. **"跳转到某一块"不能挂在 React effect 上**。同一页内点击时页面 id 和就绪状态都没变，effect 不重跑 → "点了没反应"。改成带重试的主动查找。
13. **导出/导入的标题会重复**（`# 标题` 既是页面标题又留在正文）。导入时去掉同名首块，导出时检测开头已有标题就不补。
14. **HMR 中间态会留一串假报错**。验证前先整页刷新，否则会把历史报错误判成新 bug。
15. **自定义块的斜杠菜单项要用 `updateBlock` 而不是 `insertBlocks`**，否则光标不在新块里，用户接着打字会打到块外面。
16. **自定义块导出要有语义结构**（`<blockquote>` 而非 `<div>`），Markdown 导出才会变成 `> ...`。
17. **zustand 选择器不能返回新造的数组/对象**。`useStore(s => s.records[id] ?? [])` 每次返回新数组 → 无限重渲染 → **整页白屏**。回退值用模块级常量。

## 12. 关键决策的"为什么"（避免新会话推翻已定的事）

- **为什么不用 Flutter 了**：网页版是硬需求，而 Flutter 的网页端是三种方案里最弱的；且现用编辑器库 `appflowy_editor` 是 **AGPL**，会把整个产品拖成必须开源；同时 Flutter 生态缺现成的多维表/白板件。
- **为什么选 BlockNote**：斜杠菜单、拖拽手柄、块菜单、嵌套**开箱即用**——正好是上次翻车的那部分（手写编辑器交互）。它核心是 MPL（可闭源），但**AI 扩展包是 GPL，所以 AI 那层自己做**。
- **为什么本地用 IndexedDB 而不是 SQLite**：一套代码通吃网页与桌面；SQLite 在网页端没法写文件。数据库层已隔离，将来换只改一个文件。
- **为什么图片用 `asset://` 而不是直接存地址**：见坑 10，这是"数据不会在几天后变成一堆破图"的关键。
- **为什么搜索先本地扫描**：个人库这个量级够用、零运维；接口已隔离，量大了换 Meilisearch。
- **为什么没有直接基于现成大底座**（AppFlowy / AFFiNE / 思源）：
  - AppFlowy 自托管被反馈限 2 用户、AI 上锁；web 端问题多
  - AFFiNE 自托管免费 10 席位但 AI 收费、手机端长期 beta、服务端为 source-available 企业许可
  - 思源全平台但界面偏传统、S3 同步接口绑订阅
  - 共同问题：**它们自带的界面/交互不是 FlowUs 的**，改造成本不小于自研，还背上跟上游版本的长期负担
  - 结论：**部件级取用**（编辑器用 BlockNote、同步将来用 Yjs 等），不做整体替换
- **授权雷区（调研结论，接新部件前先查这张表）**：
  - 🔴 AGPL/GPL：`appflowy_editor`（旧方案在用）、APITable、Karakeep、Linkwarden、Typesense、HyperFormula、Pandoc（只能当独立命令调用）
  - ⚫ 商业/受限：tldraw（生产要授权）、NocoDB（已非标准开源）、Handsontable、Tiptap Pro/AI、BlockNote 的 AI 包

## 13. 用户的偏好（新会话请照做）

1. **用户不是技术出身**。解释要用大白话，术语要配"这解决什么麻烦、没有它会怎样"；不要用"模块化""抽象层"这类词打发他。
2. **不重复造轮子**（铁律）：写任何代码前先查现成开源件；用户原话："我不是缺钱缺 token，不需要你省那点查询，你自己乱做更加浪费。"
3. **"一切皆插件"是开发方法，不是产品形态**：逐部件找现成件，能整用整用，只能用一部分就只取那部分。
4. **需求不确定时先问，一次一个问题**，问到有 95% 把握再动手；回答选项时要写清"选它意味着什么"+ 推荐 + 理由。
5. **验收口径必须诚实**：永远把「界面做完了」和「功能真能用了」分开说；上一版就是因此翻车的。
6. **交付要带证据**：不要只说"做好了"，要说"我怎么验的、看到什么"。
7. **工作节奏**：用户忙时会说"继续做，不用逐项汇报，做完一起给我验收清单"；这时就连续做、每项自验、最后一次性列清单。
8. **用户最在意的三件事**：数据不能丢（备份/恢复必须有）、功能必须是真的（不是壳）、界面操作习惯要像 FlowUs。
