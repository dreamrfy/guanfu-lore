## 1. 产品是什么

**AI 原生的块式个人知识库**（PKM / 第二大脑）。
闭环 = **捕获（剪藏）→ 整理（多维表格）→ 提炼（AI）→ 输出（导出/分享）**。

三条核心需求（用户原话归纳）：

1. **标准化的笔记编辑器**（格式不限，核心是编辑体验）
2. **互联网信息剪藏**（公众号 / 小红书 / B站 / 抖音；转发或链接；要防原文被删的本地备份）
3. **Agent 级 AI**（可自定义供应商、总结改写、**能自己挂 Skill 与 MCP**）

## 3. 工作纪律（用户定的铁律，必须遵守）

1. **不重复造轮子 / 「一切皆插件」**
   写任何代码前，先查是否已有成熟开源件（GitHub / Gitee / 论坛）。
   能整套用就整套用；只有部分合适就只取那部分；**逐部件独立选型**，不要因为选了大项目就假设它什么都有。
   已写入全局记忆（`no-reinventing-wheels`）。
2. **数据主权**：核心数据自托管（用户 VPS + Cloudflare R2），AI 走云端 API。
3. **验收口径分开写**：「界面/几何完成」与「功能已实装（点下去数据真的变）」**不能混为一谈**——
   上一版项目就是因为把"界面做完"写成"功能做完"而翻车。
4. **先给结论再动手**：不确定的需求先问，一次问一个问题。

### 5.4 数据库结构（Dexie v4）

| 表 | 主键 | 索引 | 说明 |
| --- | --- | --- | --- |
| `pages` | id | parentId, updatedAt, deletedAt, sortKey | 页面元信息（含软删字段=回收站） |
| `docs` | pageId | updatedAt | 每篇正文（BlockNote 块数组），与元信息分开存 |
| `meta` | key | — | 键值（预留） |
| `assets` | id | pageId, kind, createdAt | 图片/文件（以 ArrayBuffer + mime 存，不存 Blob） |
| `collections` | id | updatedAt | 多维表格定义（fields / views 内嵌） |
| `records` | id | collectionId, updatedAt | 表格记录（values: fieldId→值） |

## 8. 踩过的坑（17 条，接手的人务必先读）

> 这些坑都真实发生过，多数"只在运行时炸、类型检查看不出来"。

1. **`orderBy` 的字段必须有索引**。否则 Dexie 抛 SchemaError，表现为**永远停在"正在打开知识库…"**。
2. **启动流程必须有失败路径**。否则界面只会静静转圈，用户无从下手；现在失败会显示原因 + 重新载入按钮。
3. **图标库不要整包 import**。四套全量打进去产物从 1.2MB 涨到 12MB；用 `tools/gen-icons.mjs` 只打用到的。
4. **图标名打错不会报错，只会渲染空白**。`tools/check-icons.mjs` 逐条校验（曾抓出 `mingcute:table-2`、`tabler:layout-sidebar-left` 两个错误名）。
5. **注释里别出现 `*/`**。写 `@iconify-json/*/icons.json` 这种路径会提前结束块注释，构建直接失败。
6. **新页面标题不要设成字面量 `"无标题"`**，否则用户点进去打字会接在后面（"无标题磷化工笔记"）。空标题交给 placeholder。
7. **固定宽的侧栏 + 右栏会挤死主区**（574px 视口下主区只剩 26px）；窄窗要让右栏浮起来。
8. **用脚本模拟拖拽时事件之间要留时间**。`dragstart` 里设的 React 状态是异步生效的，紧接着发 `dragover` 会读到"没在拖拽"——**容易误判成应用 bug**。
9. **删页面要留退路**。删掉最后一篇时自动补一篇空页，否则界面没东西可开。
10. **图片绝不能把 `blob:` 地址写进文档**。blob 地址只在当次打开有效，写进库下次打开全是破图。文档里存 `asset://附件id`，显示时换、写库前换回。
11. **窄屏浮层会盖住正文**，自动收起可以，但**不能写进用户偏好**。
12. **"跳转到某一块"不能挂在 React effect 上**。同一页内点击时页面 id 和就绪状态都没变，effect 不重跑 → "点了没反应"。改成带重试的主动查找。
13. **导出/导入的标题会重复**（`# 标题` 既是页面标题又留在正文）。导入时去掉同名首块，导出时检测开头已有标题就不补。
14. **HMR 中间态会留一串假报错**。验证前先整页刷新，否则会把历史报错误判成新 bug。
15. **自定义块的斜杠菜单项要用 `updateBlock` 而不是 `insertBlocks`**，否则光标不在新块里，用户接着打字会打到块外面。
16. **自定义块导出要有语义结构**（`<blockquote>` 而非 `<div>`），Markdown 导出才会变成 `> ...`。
17. **zustand 选择器不能返回新造的数组/对象**。`useStore(s => s.records[id] ?? [])` 每次返回新数组 → 无限重渲染 → **整页白屏**。回退值用模块级常量。

### 9.11 同步层落地（2026-11-13 续，决策 D4 的 S1+S2）

**服务端**（`server/src/cloud/syncStore.ts` + 剪藏服务同一进程、同一 Token）

| 表 | 作用 |
| --- | --- |
| `sync_rows` | 每行的当前版本号（乐观锁基准） |

接口：`POST /api/sync/pull`（增量拉）、`POST /api/sync/push`（推 + 冲突判定）、`GET /api/sync/conflicts`、`POST /api/sync/conflicts/resolve`（保留服务器版 / 采用我的版本）。

**客户端**（`app/src/data/sync.ts` + 工具栏「同步」按钮）

- 本地 `outbox` 队列：**同一行的多次改动只留最新一条**（打字 10 次不会堆 10 条）；
- 拉取按游标增量、写入本地库并刷新内存；推送按乐观锁，**推不上去的存成本地冲突副本**（绝不静默丢）；
- 面板显示「待推送 N / 冲突副本 N / 上次同步时间」，可立即同步、可逐条处理冲突。

**端到端实测（本地服务 + 浏览器）**：改名 → 推送 1 条 → 服务器收到；模拟另一台设备推新版 → 本机拉取 2 条；本机拿旧版本号再推 → 服务器判冲突 → 本地存副本 → 徽标显示 1 → 「保留服务器版」后归零。**云端也已部署同一套接口**（VPS 上 `POST /api/sync/pull` 实测可用）。

⚠️ **边界（下一批要补的）**
- 只同步 **pages / collections / records** 三类实体；**附件（图片）不同步**——`asset://` 引用在别的设备上取不到，跨设备时图片会缺。
- 冲突判定是**行级乐观锁**，不做块级合并（块级合并就是用户提的「AI 冲突辅助」，尚未实现）。
- 拉取会覆盖本地同一行（服务器为准）；本地有未推送改动时，靠"推送被判冲突 → 存副本"兜底。
- 同步地址与 Token 复用「快速剪藏 → 剪藏服务地址」；**目前要手动点「立即同步」**，定时/后台自动同步下一批。

**实测**：浏览器里写一句「这周的排期定在周三，验收口径不变。」→ 问「排期定在什么时候」→ 命中该段、给出出处卡片 → 点出处能跳回原文那一段（编辑器获得焦点）。

⚠️ **边界**
- **没配 embedding Key 时自动退化成纯关键词检索**（功能不残废，只是"换个说法"可能命中不了）。
- 向量**按需生成**：第一次提问现算，之后按文本指纹增量；库里几千段时首次会慢。
- 检索范围＝**页面正文 + 剪藏记录正文**；图片里的文字不参与检索。
- 出处是"检索到的片段"，严格模式靠提示词约束模型照实标注；模型是否照做取决于模型本身。
- 向量**不参与同步**（每台设备自己算），跨设备不会传向量。

**测试**：网页端 20 个测试文件 / **162 条全绿**（新增 `ragIndex.test.ts`、`ragAsk.test.ts`：分词、切块、BM25 排序、RRF 融合、严格/宽松提示词、出处编号）。

### 9.13 AI 冲突辅助（2026-11-13 续，用户提的需求）

**规则（用户原话）**：冲突的内容**不是同一个位置** → 直接合并进云端最新；**是同一个位置** → 继续保留在副本。

| 环节 | 实现 | 说明 |
| --- | --- | --- |
| 取服务器当前版本 | 服务端新增 `GET /api/sync/row?entity=&entityId=`（已上 VPS） | 客户端做差异对比要用 |
| 差异高亮 | `app/src/data/conflictAi.ts` 的 `diffBlocks` | 按**块 id** 做 LCS 对齐，分「同一处 / 仅服务器有 / 仅我有」 |
| 硬判定 | `hasSameSpotChange` | 同一块 id 文字不同 → 判定"同一处" → **一律不自动合并**，副本保留（合并只会丢掉一边） |
| AI 语义判定 | `buildJudgeMessages` / `parseJudge` | 处理"段落被整体重写、块 id 都变了"这种按 id 看不出来的情况；模型只输出 JSON 判定，**不直接改数据** |
| 合并 | `mergePayloadBlocks` | 服务器的编辑 + 我的新增**都保留**，按服务器当前版本号当基准推上去 |
| 界面 | 同步面板每个冲突多一个「AI 判定并合并」 | 显示判定理由 + 差异高亮行（橙=同一处、蓝=仅服务器、绿=仅我有） |

**实测（浏览器）**：
- 不同位置 → 模型判"不是同一处" → 自动合并并推送成功 → 冲突副本清零（徽标从 2 → 1 → 0）。
- 同一位置（同一块 id、两边文字不同）→ 判定"同一段被两边各改过一次…副本已保留" → 差异行显示「同一处：…（我：…）」→ **冲突仍在**（徽标保持 1），不会静默丢我的版本。

⚠️ **修掉的两个 bug**
1. **合并会丢掉我新增的块**：原来只按 id 更新已有块的文字，新插入的块直接消失 → 改成按差异序列**重建块数组**。
2. **payload 形状认错**：正文块在**顶层**（`{page, blocks}`），解析函数只认 `page.blocks` → 一律判成"表结构，不做自动合并" → 两种形状都认。

**测试**：网页端 21 个测试文件 / **174 条全绿**（新增 `conflictAi.test.ts`：差异分类、合并保留新增块、JSON 解析容错、提示词内容、payload 两种形状）；服务端 **28 个自测脚本全通过**（`sync-api.selftest.ts` 增补取行接口用例）。

### 9.14 服务器剪藏箱：微信转发进来的剪藏，客户端一键导入（下一个大块·第一段）

**闭环补齐的那一环**：微信客服转发 → 服务器每 5 分钟自动收进 R2（这条链路 2026-11-06 就跑通了）→ **但客户端一直看不到**。这一段把它接上。

| 层 | 内容 | 位置 |
| --- | --- | --- |
| 服务端 | `GET /api/clips`：清单（R2 的 `clips/index.json`） | `server/src/cloud/clipApi.ts` |
| 服务端 | `GET /api/clips/:id`：正文 + 图片**签名取件码** + 原文快照（自包含 HTML） | 同上 |
| 服务端 | `GET /api/asset?key=`：图片**代理**（浏览器直连 R2 会被 CORS 拦，桶不用配 CORS） | `server/src/clipServer.ts` |
| 客户端 | 「快速剪藏 → 服务器剪藏箱」：列出服务器上的剪藏，一键「导入」 | `app/src/data/clipBox.ts`、`shell/ClipDialog.tsx` |
| 客户端 | 导入时：图片下载进本地附件库 → 快照里的图片引用改成 `asset://` → 正文按段落建块 → 写进「剪藏库」记录 | 同上 |

**实测（对真实 R2）**：清单返回 **20 条**微信转发的公众号文章；导入一条 → 剪藏库里生成记录，**4 张图 + 原文快照**都落进本地附件库；快照 7KB、图片 239KB 级别都在本地。

⚠️ **边界**
- 服务器给的是 **5 分钟有效的签名 URL**，导入时必须把图片下载到本地（已做），否则过一会儿图就失效。
- 只支持 `assets/` 前缀的资源代理；其他前缀一律拒绝。
- 导入是**新增一条记录**，不会自动去重（同一篇再导入会多一条）——去重规则下一批补。
- 剪藏箱按需拉取（展开时才请求），不常驻轮询。

**测试**：网页端 22 个测试文件 / **176 条全绿**（新增 `clipBox.test.ts`：快照图片引用改写）。

### 9.15 导入去重 + 浏览器扩展（剪藏任意网页）

| 内容 | 实现 | 说明 |
| --- | --- | --- |
| 导入去重 | `app/src/data/clipBox.ts` | 剪藏库里已有同一篇（按 `__biz/mid/idx/sn` 指纹判重）→ 提示"之前已经导入过，跳过"，不再新增记录 |
| 服务端收"客户端提交的正文" | `server/src/clipApi.ts` 的 `POST /api/clip` 新分支 | 请求体带 `html` 时：清洗（去脚本/样式）→ 抽纯文本 → 落 R2 → 返回剪藏记录。**服务端只信清洗后的内容** |
| 浏览器扩展 | `extension/`（manifest v3 + content.js + popup） | 页面上出现「✂ 剪藏」按钮；或从扩展弹窗「剪藏当前页」；抓渲染后的正文（去掉 script/style/iframe）→ POST 给剪藏服务 → 进同一个 R2 桶 → 网页端「剪藏箱」里可见 |

**为什么正文由浏览器抓、服务器不自己抓**：普通网页正文要渲染才有，服务端直接拉 HTML 常常拿到空壳（公众号那套 `js_content` 解析只对公众号有效）。扩展在渲染后的页面里取最准；服务器负责清洗与存档。

⚠️ **边界**
- **https 页面调 http 服务会被浏览器拦**（混合内容）：本机自测用 `http://127.0.0.1:8787`（浏览器视为可信来源），云端要等域名 + HTTPS。
- 只剪**整页**，没有"划线高亮"（划线要等编辑器侧的选区协议，下一批）。
- 扩展抓到的正文截断到 200KB；正文里登录后才可见的内容，扩展抓到什么就是什么（不绕过权限）。
- 客户端提交的剪藏 `source` 记为 `unknown`（`SourcePlatform` 里没有 generic 网页这一项，先不改枚举）。

**测试**：网页端 22 个测试文件 / **176 条全绿**；服务端 **28 个自测脚本全通过**（`clip-api.selftest.ts` 增补"提交 HTML"分支：脚本被清洗、正文抽成纯文本、落库一条）。

### 9.16 客户端自动同步（2026-11-13 续）

| 内容 | 实现 | 说明 |
| --- | --- | --- |
| 定时自动同步 | `app/src/data/syncAuto.ts` + `store.startAutoSync/stopAutoSync` | 每 15 秒检查一次：**有本地改动就立刻推**，否则每 60 秒拉一次；启动时先来一次 |
| 失败退避 | `shouldAutoSync` 的 `lastErrorAt` | 连不上服务器时**退避 60 秒**再试，不每 15 秒打一次服务器 |
| 开关 | 同步面板里的「自动同步」勾选 | 关掉就只保留手动「立即同步」 |
| 状态 | `syncStatus` 增加 `lastErrorAt` | 失败不弹错（避免打扰），只在面板里显示"还没同步过" |

⚠️ **边界**
- 自动同步**依赖剪藏服务可达**：没配服务或服务没起时，会安静地失败并退避（不会反复弹错）。
- 目前同步的是 **pages / collections / records**；**附件（图片）还不跟着同步**（下一项）。
- 同步是**整行覆盖**（行级乐观锁），不做块级合并（块级=AI 冲突辅助，已在 9.13）。

**测试**：网页端 23 个测试文件 / **181 条全绿**（新增 `syncAuto.test.ts`：调度规则与退避）。

### 9.18 模型选型决策记录（2026-11-13，用户参与逐项敲定）

#### D. 本轮的方法教训（下次取证照做）

1. **要看某个 App 到底收到了什么意图**，用系统事件日志，不要靠截图：
   `adb logcat -b events -d | grep wm_create_activity` —— 数组第 5~7 位就是 `action / mimeType / data` 原文。
2. **`dumpsys package` 的 resolver table 是按 scheme 与 type 分组重复打印的**，同一个组件会出现很多次。只读第一段会漏掉过滤器，得出错误结论（我本轮就这样误判过一次，被事件日志推翻）。**必须读全。**
3. **判断「预览框里是文件还是文字」，只看预览框**：文件会渲染成「文件图标 + 文件名」，文字会渲染成「文字 + 复制按钮」。
   ⚠️ **不要用「网格里有没有微信/短信」去反推载荷类型**——我本轮这么推过，后来被实测推翻：微信本身就声明了 `SEND image/video/text`，`application/zip` 的分享目标实测有 53 个、**微信在里面**；而且 chooser 的应用网格是**分页**的，首屏没有不等于没有。

## 12. 关键决策的"为什么"（避免新会话推翻已定的事）

- **为什么不用 Flutter 了**：网页版是硬需求，而 Flutter 的网页端是三种方案里最弱的；且现用编辑器库 `appflowy_editor` 是 **AGPL**，会把整个产品拖成必须开源；同时 Flutter 生态缺现成的多维表/白板件。
- **为什么选 BlockNote**：斜杠菜单、拖拽手柄、块菜单、嵌套**开箱即用**——正好是上次翻车的那部分（手写编辑器交互）。它核心是 MPL（可闭源），但**AI 扩展包是 GPL，所以 AI 那层自己做**。
- **为什么本地用 IndexedDB 而不是 SQLite**：一套代码通吃网页与桌面；SQLite 在网页端没法写文件。数据库层已隔离，将来换只改一个文件。
- **为什么图片用 `asset://` 而不是直接存地址**：见坑 10，这是"数据不会在几天后变成一堆破图"的关键。
- **为什么搜索先本地扫描**：个人库这个量级够用、零运维；接口已隔离，量大了换 Meilisearch。
- **为什么没有直接基于现成大底座**（AppFlowy / AFFiNE / 思源）：
  - AppFlowy 自托管被反馈限 2 用户、AI 上锁；web 端问题多
  - AFFiNE 自托管免费 10 席位但 AI 收费、手机端长期 beta、服务端为 source-available 企业许可
  - 思源全平台但界面偏传统、S3 同步接口绑订阅
  - 共同问题：**它们自带的界面/交互不是 FlowUs 的**，改造成本不小于自研，还背上跟上游版本的长期负担
  - 结论：**部件级取用**（编辑器用 BlockNote、同步将来用 Yjs 等），不做整体替换
- **授权雷区（调研结论，接新部件前先查这张表）**：
  - 🔴 AGPL/GPL：`appflowy_editor`（旧方案在用）、APITable、Karakeep、Linkwarden、Typesense、HyperFormula、Pandoc（只能当独立命令调用）
  - ⚫ 商业/受限：tldraw（生产要授权）、NocoDB（已非标准开源）、Handsontable、Tiptap Pro/AI、BlockNote 的 AI 包
- **为什么产品名叫「观复 / Lore」**（2026-11-14 用户拍板，**讨论终结，勿重开**）：
  - 中文"观复"取自《道德经》"万物并作，吾以观复"——产品的闭环（捕获→整理→提炼→输出）本质就是知识的循环往复，"复"是骨架；
  - 英文"Lore"＝传下来的知识，是"观复"的另一面（一个讲"回来"，一个讲"留下来"）——**互镜不互译**，与 DeepSeek/深度求索同构；
  - 正式 slogan：中文"万物并作，吾以观复。"／英文 "All things arise; I watch them return."；
  - 命名过程否决过：单字中文名、拉丁/生僻英文名（Recursus 等）、造词/复合词（Recircle 等）——教训都写在《品牌决策记录-观复Lore.md》§2；

## 13. 用户的偏好（新会话请照做）

1. **用户不是技术出身**。解释要用大白话，术语要配"这解决什么麻烦、没有它会怎样"；不要用"模块化""抽象层"这类词打发他。
2. **不重复造轮子**（铁律）：写任何代码前先查现成开源件；用户原话："我不是缺钱缺 token，不需要你省那点查询，你自己乱做更加浪费。"
3. **"一切皆插件"是开发方法，不是产品形态**：逐部件找现成件，能整用整用，只能用一部分就只取那部分。
4. **需求不确定时先问，一次一个问题**，问到有 95% 把握再动手；回答选项时要写清"选它意味着什么"+ 推荐 + 理由。
5. **验收口径必须诚实**：永远把「界面做完了」和「功能真能用了」分开说；上一版就是因此翻车的。
6. **交付要带证据**：不要只说"做好了"，要说"我怎么验的、看到什么"。
7. **工作节奏**：用户忙时会说"继续做，不用逐项汇报，做完一起给我验收清单"；这时就连续做、每项自验、最后一次性列清单。
8. **用户最在意的三件事**：数据不能丢（备份/恢复必须有）、功能必须是真的（不是壳）、界面操作习惯要像 FlowUs。
9. **需求没理清之前不要动手实现**：用户会明确说「不要着急去实现功能，你可以记录下来接下来要做什么事情，但是等我们一起确定完了你再动手」。这种阶段**只做调研、取证、归档，一行代码都不写**。他还说过「你现在不用建议我去做什么事情」——在他要求「一起确定」的阶段，**不要催促他做决定**，也不要拿待办清单轰炸他。
10. **人工测试的时机**：他不需要我每做完一小步就叫他测（「你直接把接下来的功能都做好，每做好一个小部分，你检查一下没问题，就立马接着做下一个」）；但**基础功能做到 60%~70% 时，要请他做一次完整的真人交互验收**。
11. **可以在他的真机上取证**：他会说「我操作手机，你读屏」。手机是小米（Android 17，adb 设备号 `e0cea9ba`），adb 在 `E:\dev\tools\pt\platform-tools\adb.exe`。查「某个 App 到底收到了什么」用系统事件日志，方法见 §9.19-D。

12. **凭证与浏览器授权（2026-11-15 拍板）**：凭证分三层（开发/运维/真实用户，见 §9.20）；除限权 API Token 外，用户在自己浏览器保持 Cloudflare、腾讯云控制台等的**真实登录态**——AI 需要 Token 之外的能力时，**先指出需要什么、用户确认后，才用 magpie-browser 调用本机真实浏览器操作**（完整权限，不受 Token 限权约束）。
