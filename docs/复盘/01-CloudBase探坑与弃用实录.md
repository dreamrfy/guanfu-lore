# 复盘：CloudBase 从选型到弃用的全过程（含 3 秒限制实测）

> 时间：2026-11-04 ~ 11-06｜结论先行：**CloudBase 免费体验版跑不动剪藏业务（3 秒硬限制，实测零入库），最终改走腾讯云轻量 VPS**。本篇记录完整的探索-实测-决策链，含所有弯路。

## 1. 为什么当初选 CloudBase

- P0-T06 选型时定的两阶段：阶段一 CloudBase 免费版（0 元）+ R2 免费额度，成本压到 0；
- 当时认知盲区：**不知道免费体验版的云函数有 3 秒执行上限**，也不知道 PG/文档型数据库的地域差异。

## 3. 443/430 错误的完整破案过程（云函数排障教科书）

按时间顺序的 5 层洋葱，每层修掉才露出下一层：

1. `Unzip codezip Failed` —— **PowerShell Compress-Archive 的 zip 变体腾讯解不开** → 改用 Windows 自带 `tar.exe -a -c`（标准 zip、正斜杠路径）；
2. `ResourceNotFound.Entryfile: scf_bootstrap` —— 建函数时选了「HTTP 函数」（要求容器启动脚本）→ 改选**「普通云函数」**；
3. `FUNCTIONS_INVOCATION_FAILED` + 443 + 日志无堆栈 —— **入口垫片用 ESM import，平台加载器按 CommonJS 解析** → 垫片改 `module.exports.main`；同时 package.json 去掉 `type:module`（否则 index.js 被判 ESM，module.exports 失效——本地模拟加载抓到的隐藏坑）；
4. `Dependency error` —— 「自动安装依赖」开关与包内自带 node_modules 冲突 → **关闭该开关**；
5. `FUNCTIONS_TIME_LIMIT_EXCEEDED`（3 秒）—— **最后的墙**：配置 9 项环境变量后真实链路能跑（拉到消息了），但 3 秒必被砍。实测两轮：**R2 写入 0 对象**——连一篇都没存进去。

## 4. 关键实测数据（决策依据）

| 环境 | 单轮耗时 | 入库结果 |
| --- | --- | --- |
| 云函数（免费版 3 秒） | 跑满 3000ms 被杀 | **0 篇**（两轮实测） |
| 本机（无限制） | 全链 4.4 秒/18 条 | 18 篇全进 |
| **VPS（无限制）** | 128 秒消化全部积压 | **18 篇全进，58 图全成功** |

结论公式：**微信往返 ~1s + 抓一篇带图文章 ~4s + 写 R2 ≥1s = 单篇完整处理 ≥3.5s > 3 秒上限**。免费版的结构性死刑，调触发频率救不了（游标永远推不到落盘点）。

## 5. 顺手发现的「环境陷阱」（ anyone 用 CloudBase 前必查）

- **PG 模式环境没有文档型数据库**（菜单里根本没有那个入口），且 PG 实例「跟随环境生命周期」**无法单独关闭**——空转烧 ~40 点/天（实测两天 65.33 点，用户一度以为是 AI 消耗的）；
- 云函数运行时要选 **Node 24.11（公测）**，默认是 20.19（不认 .ts 直接 443）；
- 免费版执行超时锁死 3 秒（个人版才解锁 300s+），**建函数前先看「执行超时」能不能加**——这是判断套餐够不够的第一指标；
- 资源点计费：1000 点=1 元；PG 0.342 元/核时；免费版不支持按量付费（烧完只停服不扣钱——这是好事）。

## 6. 最终处置

- CloudBase 环境 `biji-gcsb` **停用不删**（云函数 bijiapp-poll 保留，代码可随时回迁）；
- 已投入的代码资产全部复用：R2 存储层、凭证直读、轮询主循环原样搬进 VPS 版；
- 决策方法论沉淀：**「能不能跑」用实测回答，「跑多快」用数据回答**——3 秒墙不是猜出来的，是两轮 0 入库量出来的。
