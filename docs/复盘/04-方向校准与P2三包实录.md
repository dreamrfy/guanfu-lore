## 三、方向校准（本篇核心）

用户对照真实 FlowUs 用法（新建菜单/剪藏多维表/斜杠命令三张截图）指出：**主次颠倒**——
心脏是「剪藏文章资料库」（多维表，文章为记录行，可切视图），纯笔记只是配角；

三轮问答确认：第一屏=侧栏+剪藏库表格视图；多维表 v1=最小可用（表格视图+剪藏自动写入+记录打开成页面，属性系统/多视图延后）；编辑器=所见即所得（FlowUs 式 / 菜单 + Markdown 快捷输入，底层存 Markdown）。

**产品心智定型：「一切皆页面」——多维表是页面树里的特殊页面类型，剪藏管线是往用户自己搭的表里写记录的自动化。软件出厂空白，骨架用户自己搭。**

## 四、本阶段踩坑与技巧（跨项目通用）

1. **Flutter Windows 图标树摇误裁**：IconButton 空白圈（安卓正常）→ `--no-tree-shake-icons`；固化进 scripts/build-windows.sh
2. **windows/runner C++ 源文件纯 ASCII**：中文被 MSVC GBK 代码页判 C4819 警告升级错误
3. **活库逐文件拉取竞态**：App 运行中 SQLite checkpoint 把字节在 db/wal 间搬动（拉完 12KB 转眼 45KB、wal 消失）→ 停 App + 设备侧单 tar + 单文件拉取
4. **python sqlite3 不 close 的幽灵突变**：解释器退出时干净关闭会 checkpoint 并删 wal/shm——备份工件的计数查询一律在临时副本上做
5. **adb 长按拖拽 UI 自动化**：`input swipe` 的立即移动会取消 LongPress 手势 → API 34+ 用 `input motionevent DOWN/MOVE/UP` 分段注入（DOWN 后 sleep 0.8s 触发长按）
6. **`adb shell wm size 2600x1500`**：模拟器秒变宽屏验证响应式分栏（注意逻辑像素=物理÷像素比，900 逻辑宽断点需 2600 物理），测完 `wm size reset`
7. **PowerShell 5.1**：native 命令 stderr + Stop 偏好 = NativeCommandError 假死 → ErrorActionPreference 用 Continue + 显式检查；`$var` 在 Git Bash 双引号里被展开 → 复杂脚本一律写 .ps1 文件
8. **条件导出共享类漏 export**：StorageStats 类型在调用方不可见 → export 链要带上 common 文件
9. **drift_flutter 库目录（documents）≠ path_provider 资源目录（support）**——统计占用时别猜路径
10. **file_picker 13.x API 重构**：静态 `FilePicker.pickFiles`（无 .platform/withData），PlatformFile 用 `readAsBytes()`、内建 `extension`
11. **分栏内嵌模式的状态刷新**：onClosed 后必须 _reload()，否则树显示删除前的旧快照
12. **镜像根治**：PUB_HOSTED_URL / FLUTTER_STORAGE_BASE_URL 已 setx 进用户级环境变量，Gradle 守护进程不再缺镜像

## 五、协作模式沉淀

- **「先做下一段、合并验收」节奏**（用户提出）：连续 2~3 包后统一交验，减少验收打断——AI 侧每包仍需完整自测+证据归档，风险自担
- **方向校准的问答纪律**：用户要求「一次只问一个问题，直到 95% 信心再给方案」——本轮三轮问答（第一屏/多维表范围/编辑器形态）定案，比一次性长问卷高效
- **用户亲手操作的价值**：P1-T06 的清空确认、P2 的真实数据（用户自己在模拟器建笔记/挂图）让验收更真实；备份恢复把设备回滚到备份点属正常语义，但要向用户明确「备份点之后的变更会被回滚」
