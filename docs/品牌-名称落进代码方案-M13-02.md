# 名称落进代码方案（M13-02 · B02 · 2026-11-15 看门狗执行版）

> 依据：《品牌决策记录-观复Lore》§3/§4/§5。用户不在场，本方案按记录里已拍板的口径执行；
> 用户回来后如对某项选择不满意，单项可改（注意 identifier 只在**没有任何桌面分发**之前可白改——现在正是这个窗口）。

## 一、命名决策（三层）

| 层 | 名 | 用在哪 |
| --- | --- | --- |
| 正式显示名 | **观复 · Lore** | 窗口标题、网页 `<title>`、文档首行、安装后快捷方式语义 |
| 技术名（ASCII） | **guanfu-lore** | npm 包名、Cargo crate 名、二进制名、安装包文件名、Scoop 清单文件名 |
| 系统标识 | **app.guanfu.desktop** | Tauri identifier（决定桌面端用户数据存放路径）——与安卓壳既有 `app.guanfu.shell` 同前缀体系 |

为什么 productName 用 ASCII 而不是「观复 · Lore」：它决定安装包/更新产物文件名
（`guanfu-lore_0.1.0_x64-setup.exe`、latest.json 引用路径），CJK + 空格 + 间隔号在
NSIS/updater/Scoop 链路里是无收益的风险；显示层有自己的入口（窗口标题），不受影响。

## 三、明确不改的（记录在案）

- **仓库目录名 `E:\VBcoding\bijiapp`**：《品牌决策记录》§3 已定「历史遗留」；本地路径、
  `docs/项目归档与交接`、会话记录全部锚在它上面，改名收益为零风险巨大。**不改。**
- **安卓壳**：`applicationId = app.guanfu.shell`、显示名「观复壳」——上一批已用 guanfu 前缀落地，
  T08 真机证据锚在现有包名上，本轮不动。

- **`docs/验收证据/`、`docs/归档/`、`docs/基准/`、`requirements-v1/`**：看门狗红线，不改。
- **UI 界面内部文案**：属 B03 双语化/M13-03 的《品牌与文案》范围，本轮不碰。

## 四、identifier 改名的安全性（为什么现在是白改窗口）

Tauri identifier 决定 WebView2 用户数据目录（localStorage/IndexedDB 实际落盘位置）。
`cn.bijiapp.desktop` 下**没有已分发的安装**（D01 一直 BLOCKED，没出过安装包），
开发机 tauri dev 的本地数据可弃。一旦分发过再改＝用户数据"搬家"，所以 M13-02 的期限
「第一版桌面壳分发给任何人之前」就是现在。
