## 1. 这包解决什么问题

一句话：**手机和电脑都离线改了同一篇笔记，联网后怎么不打架、不丢字。**

典型场景：周一你在手机上给《Linux 入门》补了段笔记，周二在电脑上给同一篇换了标签，两台设备都断着网。周三都联网了——这两份修改怎么合？

## 2. 需求文档已经替你定死的事（不用再选）

| 需求 | 大白话 |
| --- | --- |
| SYNC-02 | 检测到「两台设备改了同一篇」时，**必须两边都保留**，谁新谁覆盖、按时间戳抢跑都不允许 |
| SYNC-03 | 冲突页**必须同时提供三种处理**：手动合并成新版本 / 分别保留两页 / 稍后处理 |
| SYNC-04 | 提交合并前**再查一遍云端**（防止合并期间对方又改了）；没处理冲突时，本机照常能写能存，但不能假装「已同步」 |
| SYNC-05 | 正文、属性、属性删除、视图、目录移动、导图全部适用同一套策略；**「一台删除 vs 另一台编辑」相撞不能悄悄吞内容** |
| SYNC-01 | 联网先同步轻量目录（标题/标签/简介），正文按需下载；断网不清空已有资料 |

所以任务表里「三选一」的真正含义不是「只做一个」，而是——**冲突页打开时，默认引导你用哪一种**（见第四节）。

## 3. 方案草案（实现蓝图）

### 3.1 版本号：给每篇内容一张「取件牌」

每篇页面/记录随身带三个号：

- **rev（版本号）**：云端每被改一次 +1，像储物柜的取件牌
- **baseRev（我基于哪版改的）**：设备离开云端时揣走的号码
- **changes（改了哪些字段）**：本机记下「我动了正文、标签」，而不是「我动了这一篇」

联网上传时：设备说「我基于第 18 版改了标签」。云端一看自己还是 18 → 直接收下（**快路径，99% 的情况走这里**）；云端已经到 20 了 → 分叉，进冲突流程。

### 3.2 自动合并的边界（方案核心主张，按 SYNC-02「由方案验证」授权）

| 两台设备改了什么 | 处理 |
| --- | --- |
| **不同字段**（一台改正文、一台改标签） | **自动合并**，两边都生效，不打扰你（因为互不覆盖、零丢失） |
| **同一字段都改了**（都在正文里写字） | 进冲突页（机器无法确认无损，不交给 AI 瞎合） |
| 一台删除、另一台编辑 | 进冲突页（SYNC-05：不能吞内容） |
| 属性「定义」被删 vs 别人填了值 | 进冲突页 |

> 标题、来源、标签这类短字段未来可做「并排展示一键选」，但第一版一律走冲突页，宁可多问你一次。

### 3.3 冲突页长什么样

```
┌─────────────────────────────────────────────┐
│ ⚠ 这篇内容在两台设备上都有修改               │
│                                              │
│ 📱 手机（11-10 周一）：改了正文              │
│ 💻 电脑（11-11 周二）：改了正文              │
│                                              │
│ [并排看差异 ▾]   共同版本：11-09 的第 18 版 ↗ │
│                                              │
│ ┌──────────┐ ┌──────────┐ ┌──────────┐     │
│ │ 手动合并  │ │ 保留两页  │ │ 稍后处理  │     │
│ │ (存为新版)│ │ (推荐⭐)  │ │ (本机继续存)│   │
│ └──────────┘ └──────────┘ └──────────┘     │
└─────────────────────────────────────────────┘
```

- **保留两页**：选哪份继续用原页面身份，另一份成为副本并注明「来自手机 11-10」；已有双链不断、不静默重定向（SYNC-03）
- **手动合并**：左右对照，逐段勾选要哪边，保存成**新版本**（旧版进历史，不覆盖）
- **稍后处理**：冲突页不消失、目录里挂角标；期间本机输入持续保存（SYNC-04）
- **提交前复检**：点任一按钮时再查一次云端，有新修改就再提示（SYNC-04）
- **版本恢复**：任何恢复都是「生成新版本」，当前内容与未同步分支永不抹掉（SYNC-05）

### 3.4 同步节奏（贴合剪藏场景）

- 剪藏文章（服务端产生）：只增不改，天然无冲突，目录轻量同步即可
- 你自己写的笔记/属性/视图：走上面的版本号机制
- 浏览器端离线是「尽力而为」（OFF-05：浏览器缓存可能被系统清），安卓/Windows 才是可靠离线——这条会如实写进兼容说明

## 4. 需要你拍板的唯一问题

三种处理都会做（需求基准），但要定：**冲突页打开时，默认把哪种放在「推荐」位？**

| 选项 | 适合 | 代价 |
| --- | --- | --- |
| **A. 保留两页（我的推荐）** | 最安全：不丢任何字，事后在原页里整理；点一下就完事 | 库里会多副本，需要你偶尔清理 |
| B. 手动合并为默认引导 | 库最干净，一步到位 | 每次冲突都要花 1-2 分钟对照，嫌麻烦的人容易拖着不处理 |
| C. 按情况智能建议 | 改动小→引导合并；改动大→引导保留两页 | 第一版规则简单，智能有限；后期可升级 |

我的推荐理由：冲突是低频事件（你一个人用，两台设备同时改同一篇的机会不多），低频事件选「最不会出错」而不是「最高效」。

## 5. 诚实口径（本草案没承诺的事）

- 未联网设备的修改只能在它联网后检测到——同步方案不能「预见」还没上云的改动（SYNC-04 原文口径）
- 自动合并的「不同字段」判定依赖字段级变更记录，第一版先覆盖正文/标题/标签/属性值；视图布局、导图结构第一版一律进冲突页
- 本草案是设计承诺，不是已实现功能——实现细则（P7 阶段 11 个任务包）会另出技术文档
