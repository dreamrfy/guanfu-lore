# 方案：FlowUs 心智模型对齐调整 v1（2026-11-08，用户已批准）

> 起因：P2-T01~T03 实施后，用户对照自己真实的 FlowUs 使用方式（截图三张），指出主次颠倒——
> App 的心脏是「剪藏文章资料库」（多维表），纯笔记编辑只是配角。本方案经三轮问答确认（第一屏/多维表 v1 范围/编辑器形态），用户批准执行。
> **本文件是调整后的执行基准，与《P0-T08 第一版范围冻结 v1》冲突处以本文件为准。**

## 一、心智模型（一句话锁定）

**「一切皆页面」**：侧栏页面树里的每一项都是页面；普通页面 = 块编辑器；多维表 = 表格视图页面；
剪藏文章 = 用户自己搭的多维表里的记录（可打开成页面：原文快照 + 批注）。
软件出厂空白，骨架由用户自己搭——剪藏库是用户的第一个搭建成果，剪藏管线是往里写记录的自动化。

## 二、用户真实工作流（设计的锚点）

1. 微信看到好文章 → 转发进剪藏管线（服务端已上线，自动入库 R2）
2. 打开 App → 剪藏文章已作为**记录**出现在自己搭的多维表里（带来源/标签/时间）
3. 点开记录 → 看原文快照 → 在上面**写批注笔记**（上课在讲义上做标记那种）
4. 纯笔记/自己的整理是配角；**看网络信息 + 对信息编辑批注才是主循环**

## 三、与冻结计划的调整对照

| 原计划 | 调整后 | 理由 |
| --- | --- | --- |
| P3 属性系统+六视图在编辑器之后 | **多维表最小版提前**：新页面类型「多维表」+ 表格视图（建列/建行/编辑单元格）+ 剪藏自动写入指定表 + 记录打开成页面（快照+批注） | 核心工作流心脏，不能排最后 |
| P3 七种属性类型 | **延后**（第一版多维表先只做文本列） | 最小可用先行 |
| P3 看板/日历/画廊等视图 | **延后** | 同上 |
| P7 双向同步 | **单向拉取提前**：App 从服务端拉剪藏文章写入指定多维表（双向后置） | 让剪藏文章先进 App，闭环跑起来 |
| 编辑器菜单切类型 | **FlowUs 化**：输入 `/` 弹块菜单 + Markdown 快捷输入（`#`+空格→标题、`-`→列表、`**`→粗体已做） | 用户截图三的交互 |

## 四、已做工作的处置（不浪费）

- P2-T01~T03 **全部保留**：它们就是 FlowUs「普通页面」的底座——树形侧栏、分栏打开、块编辑器
  正是 FlowUs 的骨架（用户截图三的 / 菜单与块列表即此形态），只差 slash 菜单与快捷输入这层皮
- 块编辑器正文格式不变；多维表作为**新页面类型**挂进同一棵树、同一个存储

## 五、执行顺序（调整后的包）

1. **页面类型系统**：新建时可选「页面 / 多维表」；空页面内嵌类型选择器（仿 FlowUs 截图一）；侧栏图标区分
2. **多维表最小版**：表格视图（建列/建行/编辑单元格/删列删行）+ 数据入库
3. **记录详情页**：点记录打开成页面（原文快照 + 批注区），记录↔页面双向定位
4. **剪藏入库通道**：设置「剪藏目标表」→ App 拉取服务端文章写入 → 记录带来源/标签/时间（单向拉取）
5. **编辑器 FlowUs 化**：`/` 菜单 + Markdown 快捷输入
6. 回归原计划：MD 导出导入 → 中文长文性能 → 属性系统 → 更多视图 → 同步双向化 → ……

## 六、明确后置（本轮不做）

看板/日历/画廊/时间轴等视图、七种属性类型、AI 助手、引用页面/页面内嵌、文件夹类型、
模板/导入、双向同步、收集表——全部记入后续阶段，不在多维表最小版内。

## 七、验收基准（多维表最小版）

- 新建页面时能选「多维表」类型，侧栏图标与普通页面区分
- 表格视图：加列（文本）、加行、编辑单元格、删行，重启数据在
- 剪藏文章自动出现在指定表的记录行（含来源/时间）
- 点记录 → 打开页面：原文快照可见 + 批注可写 + 保存链（状态灯/草稿/恢复）全部生效
