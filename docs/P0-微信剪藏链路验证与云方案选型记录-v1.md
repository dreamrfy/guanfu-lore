# 第一部分 · 结论基线

## 0 一句话结论

微信"转发一篇公众号文章"这条链路**已经真机跑通**：用户在企业微信「微信客服」会话里转发文章，服务端能拿到 `msgtype=link` 的消息，**含完整文章 URL、标题、缩略图**。服务端选型为先跑「CloudBase 免费环境 + 图片放 Cloudflare R2」的 0 元起步组合。

## 2 已排除的路线（含原因，避免重复踩坑）

| 路线 | 为什么排除 |
| --- | --- |
| **走公众号接收转发** | 手机实测：微信转发面板里**没有公众号**。公众号只能"打开会话→粘贴链接→发送"，比"转发"多好几步；印象笔记官方说明也证实它走的是"复制链接+粘贴发送"。违背需求 CLIP-01「复制链接、剪贴板粘贴不是可接受的替代方案」 |
| **走企业微信"加好友"（外部联系人）** | 想把"企微好友"发来的消息**程序化读出来**，只能开「会话内容存档」：需主体验证/认证（**300 元/次，一年一续**，通常要营业执照）+ 会话存档（读外部联系人的**服务版约 300–450 元/账号/年**，官方调过价）+ **需外部联系人同意**。成本与门槛对个人项目过高 |
| **免费隧道当生产回调地址** | `loca.lt`（间歇 502/408、进程自行退出）、`localhost.run`（映射不生效，返回 "no tunnel"）、`serveo.net`（进程退出）实测**全都不稳**。**这条坑很重要：回调地址必须由真服务器提供** |
| **cloudflared（Cloudflare Tunnel）** | GitHub 下载被重置（开发机直连不通），且本机 shell 环境 1.1.1.1 不通，无法使用 |
| **微信云托管（cloud.weixin.qq.com）** | 需小程序/公众号主体；本账号是**个人未认证**公众号，能否开通不确定，且官方指引页当前 404。改用腾讯云开发 CloudBase（官方文档明确写着云开发控制台「适合个人开发者和常规项目」） |
| **把视频本体存进服务器** | 明确排除，成本极不合理 |
| **自己电脑 + 隧道跑常驻服务** | 电脑关机即中断，无法满足"3 天内必须拉取"的硬要求 |

## 4 数据模型与命名约定（把"剪藏"讲清楚）

**剪藏 = 把在线文章抄一份自己能永久保管的副本**：原文删了/图被清了，你那份还在。**这就是剪藏与"存个链接"的本质区别。**

一条剪藏包含四类内容：

| 类别 | 放哪 | 体积量级 |
| --- | --- | --- |
| ① 目录信息（标题、作者、来源、原始链接、收藏时间、标签、处理状态） | 数据库 | 几百字节 |
| ② 正文文字与排版 | 数据库或文件 | 几十 KB |
| ③ **文章里的图片**（含封面） | **对象存储（R2）** | **1–3 MB/篇（大头）** |
| ④ 导出的离线 HTML/PDF【建议待确认：按需现生成】 | 对象存储 | 几百 KB–几 MB |

**为什么图片必须自己存**：微信公众号的图是**热链**——图在微信服务器上，文章里只是地址。原文删除或图片被清理，地址就变空白。对应需求 SNAP-01「资源自存，不依赖原文热链」。

**资源引用约定【建议待确认】**：
- 数据库里存 `asset_id`（编号）+ `provider`（哪个存储）
- **不存**完整 URL；App 读取时由服务端按编号生成实际地址
- 好处：将来换存储 = 改一个配置，不用改任何文章内容

> 数字为 **2026-11-04 查取的官方数值**，会变；以官方页面为准。
> 换算基准：CloudBase **1000 资源点 = 1 元**。

### 5.1 免费与付费对照

| 项目 | CloudBase 免费体验环境 | CloudBase 个人版 | 香港轻量服务器 | Cloudflare R2 |

### 5.3 本项目用量估算（每 30 分钟轮询 + 每月约 600 篇）

| 消耗项 | 估算点数/月 |
| --- | --- |
| 云函数（调用+资源） | ~7 点 |
| 数据库调用 | ~50 点 |
| 云存储请求 | ~50 点 |
| 云存储容量（每月增约 1.2GB） | ~830 点（第一年末 ~1,650 点） |
| 看图流量（每月真读约 100 篇） | ~42 点 |
| **合计** | **约 980–1,800 点/月** |

**结论**：CloudBase 免费 3000 点/月**够用**。因为图片被 R2 接走后，CloudBase 只剩文字与数据库，月耗约 **110 点（用掉 3.7%）**。

**判断标尺**：CloudBase 免费额度本身大约能撑 **~20GB 图片存量**；改用 R2 存图后，瓶颈变成 **R2 的 10GB 免费额度 ≈ 约 5,000 篇剪藏**，超出后约 0.11 元/GB/月。

### 5.4 轮询频率与成本的关系（重要，别过度设计）

- 每 5 分钟轮询 = 8,640 次/月 → 成本仍然很低，但**没必要**
- **每 30 分钟** = 720 次/月，最坏延迟 30 分钟，**远小于 3 天窗口** → 推荐
- 每 1 小时也可以
- 结论：**轮询成本几乎可忽略，真正的成本只有"图片存了多少 GB"**

## 7 抓取可行性（预探实测 + 底线决策）

> 2026-11-04 用已转发的那篇文章（《极简热榜回归初心…》）做预探。原始记录见附录 H。

### 7.1 【已实测】可行（3 条好消息）

| 结论 | 证据 |
| --- | --- |
| **正文可直出** | HTML 内存在 `js_content` 正文容器，服务端直出，**不需要渲染** |
| **图片无防盗链** | 同一张图，在"仅带 UA / 带 UA+Referer / 完全裸请求"三种情况下**都返回 `200` + `image/png`**（魔数 `89504e47`）→ **"图片自存"这条路是通的** |
| 未被风控拦 | 页面内无"环境异常 / 去验证 / 访问过于频繁 / 请在微信客户端打开"等提示 |

### 7.2 【已实测】3 个实现坑（不处理就会漏内容）

| 坑 | 表现 | 处理方式 |
| --- | --- | --- |
| **不带浏览器 UA 会被拦** | 裸请求返回 **302**；带常规浏览器 UA 才 200 | 请求必须带常规浏览器 UA |
| **懒加载图在 `data-src`** | 11 个 `img` 中 5 个用 `data-src`，`src` 里有一部分是占位图 | **优先取 `data-src`**，否则漏图 |
| **HTML 实体转义** | 图片地址里是 `&amp;from=appmsg` 而非 `&from=appmsg` | 必须先 unescape，否则**图片全部下载失败**（本次一开始就栽在这） |

| --- | --- | --- | --- |
| 公众号 | ✅ | — | 正文 + 全部图片 + 表格 |
| B站 | 页面是 JS 空壳 | — | **公开 API 即可**：标题、简介、封面、UP主、时长（**无需登录**） |
| 抖音 | JS 空壳，拿不到 | ✅ | 标题 + 描述 + 作者 + 日期 + 点赞数 |
| 小红书 | 未登录跳登录/404 | ✅ | 标题 + 正文描述 + 标签（登录弹层**不影响** og 分享标签） |

> **共同结论**：`真实浏览器渲染` + `URL 参数原样保留` = 四个平台都能拿到内容。

### 8.3 公众号「图片消息」（纯图/长图）【已实测】

- 这类消息转发过来也是 `link`，但 URL 形式是 `t=pages/image_detail&...`
- **静态抓取拿不到**（返回「环境异常 / 去验证」拦截页；换 URL 形式、换微信 UA 共 4 种组合均失败）
- **真实浏览器渲染 + 完整原 URL → 成功拿到**：标题 + 图文正文（579 字）+ 7 张图
- ⚠️ 关键：**URL 参数必须原样保留**（丢掉 `from_masonry` / `sharer_shareinfo` 后页面直接回「参数错误」）

### 8.4 本轮踩到的 4 个实现坑（都会导致"看起来抓不到"，务必记住）

| # | 坑 | 表现 | 正确做法 |
| --- | --- | --- | --- |
| 1 | **正文被隐藏样式吃掉** | 微信给正文容器加 `style="visibility:hidden; opacity:0"`，原样保留后**离线 HTML 打开看不到任何正文**（曾误判为"抓不到正文"） | 清洗时**删掉 visibility:hidden / opacity:0 / display:none**，并加 CSS 兜底 `#js_content{visibility:visible!important;opacity:1!important}` |
| 2 | **URL 参数必须原样保留** | 丢掉 `chksm` → 微信返回 **302「未知错误」**；丢掉 `from_masonry` → 图片消息页回「**参数错误**」 | 转发来的 URL **一个字都不删** |
| 3 | **懒加载图只有 `data-src`、没有 `src`** | 只做"替换 src"等于什么都没做，文件里仍是外部图片（不满足"自包含"） | 优先取 `data-src`；没有 `src` 时要**补一个 src**，不是替换 |
| 4 | **HTML 实体未转义** | 图片地址里是 `&amp;from=appmsg`，直接请求下载不到 | 先 unescape 成 `&` |
