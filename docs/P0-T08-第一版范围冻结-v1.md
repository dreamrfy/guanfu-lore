## 2. 技术栈与架构冻结

| 层 | 冻结为 | 一句话理由 |
| --- | --- | --- |
| 客户端 | **Flutter**（安卓 + Windows + Web） | T02 真机实测：懒加载表格丝滑；三端一致；Windows 打包待装 VS |
| 客户端数据 | **SQLite（本机）+ 资源文件落地** | 离线优先、断网不丢 |
| 服务端 | **腾讯轻量 VPS（现有机）双角色**：①剪藏轮询（已上线）②同步 API（P7-T01 起建） | 代码零重写、同一台机器、成本已含 |
| 资源存储 | **Cloudflare R2**（客户端经服务端换签访问） | 资源只存编号（G1 红线），迁移只改配置 |
| 同步冲突 | **T07 冻结方案**：rev/baseRev+字段级变更；不同字段自动合并；冲突页三按钮默认引导「保留两页」 | 需求 SYNC-02~05 全覆盖 |
| 剪藏链路 | 维持现状（微信客服→VPS 轮询→R2） | 已验收，不动 |

## 3. 需要你点头的三个口径（本次包的全部决策点）

- **A. 网页端定位「能读、能轻编辑」**：Flutter Web 大表格/长文编辑性能有限（T02 实测略卡），第一版网页端以阅读、查资料、小改动为主；重度整理在手机/Windows 做。这是任务表预埋的风险预案转正，会写进兼容矩阵（P12-T06）。
- **B. P1-T01 前置安装 Visual Studio Build Tools（免费）**：Windows 空壳打包必需，装 E 盘，约 20-30 分钟。不装则 Windows 端卡在第一步。
- **C. 其余范围与顺序照任务表原样冻结**：13 阶段 105 包、按需求 19.2 顺序推进、不跳阶段；验证期发现的问题（如失败记录无重试入口）都已有对应任务包（P5-T09），不新增需求、不删需求。
