# 真实凭证 poll 冒烟（2026-11-05）

## 结论

**通过**。真实微信客服凭证下，`gettoken` → `sync_msg` → 解析 → 抓取 → 图片下载 → SQLite 落库 → 游标落盘，全链一次跑通，耗时 4.4 秒。此前 VERSION.md「唯一未跑过的真实链路」已消除。

## 跑了什么

- 用户真机向「微信客服」转发 4 条新消息（1 公众号 + 1 B站短链 + 1 小红书 + 1 公众号 http 链接）
- 执行 `node src/cli.ts poll`（凭证走仓库外文件 `E:\dev\tmp\wecom-secrets\wecom-kf.json`）
- 服务端拉回 3 天窗口内全部 18 条消息（含 11-04 的 14 条旧消息）

## 结果

| 项 | 数 | 说明 |
| --- | --- | --- |
| 拉取消息 | 18 | 含旧消息 14 条 |
| 解析成功 | 15 | 3 条非链接类按设计跳过（与 11-04 一致） |
| 幂等跳过 | 11 | 昨日已入库的旧消息全部跳过，0 重复 |
| 新入库 | 4 | 1 complete / 2 partial / 1 failed |
| 图片 | 2/2 成功 | 公众号文章 2 图 + 离线 HTML 快照落盘 |
| 游标 | 已落盘 | 下次增量拉取从新游标继续 |

各状态判定符合红线：公众号图文完整才 complete；B站/小红书只存元数据记 partial（content_missing）；http:// 公众号链接拒抓记 failed（unsupported_type），失败原因文案可读。

## 发现（2 条，均不阻塞接云）

1. **http:// 公众号链接被白名单拒绝**：真实转发中出现了 `http://mp.weixin.qq.com/...`（来自订阅号消息原始链接）。当前口径「origin 须为 https」将其判为不支持。可选处理：对 `mp.weixin.qq.com` 做 http→https 规范化后再抓（抓取仍是 https，攻击面不变）。**待用户拍板。**
2. **B站封面未落盘**：元数据路径拿到了封面 URL，但没有下载为资源（G1 红线下记录里也不能存完整 URL）。与《接云清单》§6「封面写入记录」的说法有差距，接云时补：封面下载 → 资源落盘 → 记录存 assetId。
