# I03 端到端自验证据（2026-11-15 · 看门狗 v4 · 模块 I 收官）

## 场景

全链：**剪藏 → 自动出现在未读 → 点开标已读 → 刷新仍是已读**。

- 剪藏源：`mock-clip-server.mjs`（本文件目录内，127.0.0.1:8787）。真服务的 `/api/clips` 需要 R2 签取件码，本机无 R2 凭证，故按 `server/src/cloud/clipApi.ts` 的真实 JSON 契约实现三个只读接口（清单 / 详情含快照+图片 / 图片代理字节），客户端代码零改动、走真 HTTP。剪藏内容：1 条 `complete` 公众号文章 + 1 张 128×128 PNG（385B，`i03-img-001.png`）+ 自包含快照 HTML。
- 客户端：vite dev（localhost:5173），全新 Chrome 实例（独立 profile，IndexedDB 干净起步，进站前已 `deleteDatabase` 清库）。

## 链路实录（截图 + 服务端日志）

| 步骤 | 证据 | 实测 |
| --- | --- | --- |
| 1. 开机自动入库 | `1-开机自动入库-侧栏角标.png` | hydrate → 自动导入，侧栏「剪藏库」出现未读角标 **1**；mock 日志依次命中 `GET /api/clips` → `GET /api/clips/:id` → `GET /api/asset`（图片字节已取） |
| 2. 未读标记 | `2-收集箱列表-未读圆点.png` | 收集箱列表行号位显示蓝色未读圆点；标题/来源(公众号)/作者/原文链接/收藏时间齐全 |
| 3. 点开标已读 | `3-点开标已读-圆点消失.png` | 点开记录：详情面板**状态=已读**、圆点恢复为行号、侧栏角标消失、原文备份（下载 HTML/打开快照）在 |
| 4. 刷新持久化 | `4-刷新后仍是已读.png` | 刷新后未读角标数 = 0，已读落库持久化成立 |

## 幂等实录

刷新后 app 重新 hydrate，自动导入再次运行：mock 日志出现第二次 `GET /api/clips` + `GET /api/clips/:id`（核对服务器），但**没有** `/api/asset` 图片请求、记录仍 1 条（「1 条」计数未变）——原链判重跳过，不重复导入、不重复下载。

## 工具与复现

1. `node mock-clip-server.mjs`（8787）
2. `npm run dev`（app/，5173）
3. Chrome 调试实例：`--remote-debugging-port=9223 --user-data-dir=<新目录> --window-size=1600,1000`
4. 走查脚本 `walkthrough.mjs`（本目录，playwright-core 连 9223）：清库 → 开机角标 → 列表圆点 → 点开标已读 → 刷新持久化，截图自动落本目录。
