# P1-T04 保存状态机（2026-11-07，**已验收关包**）

> 验收标准（任务表）：断网写三段字，界面明确显示「已保存在本机」；模拟写盘失败时不显示已保存。
> **结论：用户回「通过」（与 P1-T05 合并验收）。** P1 阶段本就不联网，「断网」条件天然成立；冲突态为 P7 预留位（枚举+文案+优先级已就位）。

## 实测记录（安卓模拟器全流程，截图见同目录）

| 步骤 | 状态灯 | 结果 |
| --- | --- | --- |
| 打开笔记（未编辑） | 🟢 已保存在本机 · 等待同步 | 正确初始态 |
| 打字 `state-test-abc` → 停顿 | 🟢 已保存在本机 · 等待同步 | 防抖 800ms 自动落盘 |
| 开故障注入 → 续写 `-more` → 停顿 | 🔴 **保存失败 · 内容未写入本机** | **绝不假报已保存** |
| 关故障注入 → 续写 `-ok` → 停顿 | 🟢 已保存在本机 · 等待同步 | 自动重试成功 |
| **杀进程 → 重开 → 查库** | — | `content='state-test-abc-more-ok' rev=3`——**全旅程内容一个字没丢**（`安卓④杀进程重启后数据库实证.txt`） |

## 过程中发现并修复

- **幽灵保存**：查库时发现打开详情页可能触发一次多余的相同内容写入（rev 空跳，Welcome rev=1）。已加双守卫：`markSaved()` 基准对齐 + flush 时「与基准一致则跳过写入」；18/18 测试含专项回归
- 已知残留：Welcome 的 rev 因修复前的那次写入停在 1（内容未变、无数据影响）；P7 接同步时以 baseRev 对齐逻辑自然消化
