## 2 配置步骤（可复现）

| 步骤 | 操作 | 注意 |
| --- | --- | --- |
| 1 | 企业微信管理后台 → 应用管理 → 应用 → 自建 → 创建应用 | **应用 logo 是必填**，没上传点"创建应用"无反应且不报错 |
| 2 | 应用可见范围包含接待人员所在部门 | 否则后续"可管理客服账号"不通 |
| 3 | 我的企业 → 外部沟通管理 → 对外联系权限 → 加入相关人员/部门 | 接待人员的前置条件 |
| 4 | 应用管理 → 微信客服（基础应用）→ 进入 → 客服账号 → 创建账号 | **先建账号！** 一旦开启"通过 API 管理"后台就不能再建账号 |
| 5 | 客服账号详情 → 人工接待配置 → 接待人员 → 添加 | 不设接待人员会显示"无人接待" |
| 6 | 客服账号详情 → 取**接入链接**（同时可生成二维码） | 这个链接就是用户在微信里的入口 |
| 7 | 打开 kf.weixin.qq.com（微信客服独立后台）→ 开发配置 → 开始使用企业内部接入 | ⚠️ 企业微信后台里"通过API管理会话消息→企业内部开发"的"前往配置"会绕回首页，**真正的配置在独立后台** |
| 8 | 填 **回调URL / Token / EncodingAESKey** → 完成 | ⚠️ 保存时**微信会立即请求该 URL 验证**，服务端必须先跑起来 |
| 9 | 开发配置页取**微信客服专属 Secret** | 换 access_token 用它，**不是**自建应用那个 Secret |

**URL 有效性验证的请求形态**（本机实测收到真实请求）：

```
GET <你的URL>?msg_signature=..&timestamp=..&nonce=..&echostr=<加密串>
→ 需：验签（签名算法由协议规定）→ 解密 echostr → **把明文原样返回**
```

## 3 官方限额与硬约束

| 项目 | 规定 | 来源 |
| --- | --- | --- |
| **消息读取窗口** | `sync_msg` **只能读最近 3 天内**的消息和事件 | 官方文档 |
| **客户数上限** | 企业**未验证**时，微信客服**累计仅可接待 100 位客户**（历史累计、不重置）；认证并绑定视频号后可不受限 | 后台横幅 + 官方文档 |
| 支持的消息类型 | 文本、图片、语音、视频、文件、位置、**链接**、名片、小程序、菜单、事件 | 官方文档 |
| 媒体大小限制 | 图片 2MB、语音 2MB、视频 10MB、文件 20MB（超出会收到文本提示消息） | 官方文档 |
| 主动发消息限制 | 客户主动发消息后 **48 小时内**最多可发 **5 条**；用户继续发消息可再次下发 | 官方文档 |
| 回调 vs 拉取 | 回调只推"有新消息"的信号（含 `Token`/`OpenKfId`），**内容要主动调 `sync_msg` 拉** | 官方文档 |
| 权限要求 | 自建应用须配置到「微信客服 - 可调用接口的应用」中 | 官方文档 |

## 4 关键接口（本次实测可用）

### 4.1 取 access_token

```
GET https://qyapi.weixin.qq.com/cgi-bin/gettoken?corpid=<corpid>&corpsecret=<微信客服专属Secret>
→ 实测返回 errcode=0, errmsg=ok, 有 access_token
```

### 4.2 取客服账号列表（拿 open_kfid）

```
POST https://qyapi.weixin.qq.com/cgi-bin/kf/account/list?access_token=<token>
Body: {"offset":0,"limit":100}
→ 实测返回 1 个账号，open_kfid = wkTQVsdQAAGYCXSgPlsgIsAo7FJ3TRBw
```

### 4.3 拉取消息（核心）

```
POST https://qyapi.weixin.qq.com/cgi-bin/kf/sync_msg?access_token=<token>
Body: {
  "limit": 1000,
  "voice_format": 0,
  "open_kfid": "wkTQVsdQAAGYCXSgPlsgIsAo7FJ3TRBw",
  "cursor": "<上次返回的 next_cursor，增量拉取>",
  "token": "<回调里的 Token，可选；不填有更严的频率限制>"
}
```

**实现要点**：
- `next_cursor` **必须入库保存**，否则要每次从 3 天前重拉
- 回调里的 `Token` 10 分钟有效
- 不能靠"`msg_list` 为空"判断是否拉完（可能出现 `has_more=1` 但列表为空）

### 4.4 回调报文形态（POST）

```
POST <你的URL>?msg_signature=..&timestamp=..&nonce=..
Body: <xml><ToUserName>..</ToUserName><Encrypt>..</Encrypt></xml>
→ 解密 <Encrypt> 后得到：
   <xml>
     <ToUserName>ww...</ToUserName>
     <CreateTime>..</CreateTime>
     <MsgType>event</MsgType>
     <Event>kf_msg_or_event</Event>
     <Token>..</Token>          ← 用它去 sync_msg 拉内容
     <OpenKfId>wk...</OpenKfId> ← 哪个客服账号有新消息
   </xml>
```

## 5 用户侧交互（真机实测）

| 步骤 | 实际情况 |
| --- | --- |
| 进入会话 | 手机微信打开客服接入链接 → 出现与「贵州雨北灵大数据服务有限公司客服」的会话 |
| 会话位置 | 在微信「**客服消息**」折叠夹里（**不像普通联系人直接在最近聊天**） |
| 转发文章 | 文章右上角「…」→ 转发 → 在"最近聊天"里点「客服消息」→ 选该客服 → 发送 |
| 步数评价 | 比普通联系人**多一层**；对比 FlowUs 剪藏助手（企微加好友形态，直接在最近聊天里）多一层，但**转发本身仍是一键直达** |
