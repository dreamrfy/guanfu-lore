## 1. 结论摘要

1. **popup 定为 320×480**（现 300 宽），暖纸底 + 墨蓝主色，与主应用一致。
2. **一个主行动：剪藏当前页**；服务地址/Token 收进“设置”，首次安装才强制配置。
3. **注入按钮 32×32，悬停展开为 88×32**；只在可剪藏页面出现，Shadow DOM 隔离。
4. **划词工具条 220×36**：高亮、剪藏选中、复制链接、AI 解释；不遮挡正文。
5. **权限收窄**：`activeTab` + `scripting` + `storage`，`<all_urls>` 改为 `optional_host_permissions`，点击时按需申请。
6. **失败要说人话**：未配置/Token 无效/页面不允许抓取/网络失败/混合内容，各有文案与下一步。
7. **离线先存本地队列**，联网后重试；不让用户重复剪藏。
8. **不做阅读器、不做全站采集、不读浏览历史**；只处理用户主动触发的一页。

**状态**：
- 未配置：页面卡下显示“还没连接剪藏服务。” + “去设置”主按钮；剪藏按钮禁用。
- 已配置：正常。
- 抓取中：按钮 loading“抓取中……”，禁用重复点击。
- 成功：“已收进收集箱” + 打开收集箱。
- 失败：错误文案 + 重试；保留页面信息。

## 4. 流程

### 4.1 首次安装

1. 安装完成 → 打开选项页（`chrome.runtime.openOptionsPage`）。
2. 填服务地址 + Token → 测试连接。
3. 成功 → 提示“已连接。去任意网页试试剪藏。” → 关闭。
4. 失败 → 保留输入；给“检查服务是否启动/地址是否 HTTPS”。

### 4.2 剪藏当前页

1. 点扩展图标 → popup 读取 `activeTab` 标题/URL/favicon。
2. 可选标签 → 点“剪藏当前页”。
3. popup 调 `content.js` 抓正文（Readability 类）→ POST `/api/clip`。
4. 成功 → “已收进收集箱” + badge +1；失败 → 文案 + 重试。
5. 服务端清洗/截断 200KB；返回条目 ID。

### 4.3 微信文章

- `mp.weixin.qq.com` 页面注入按钮；正文选择器 `#js_content`。
- 图片懒加载：抓取 `data-src`；失败保留占位。
- 视频/音频：保留链接，不下载。
- 结果与浏览器剪藏同进收集箱。

### 4.4 划词高亮

1. 选中文本 → 工具条。
2. 点“高亮” → 计算 quoted fragment（原文 + 前后 32 字）。
3. POST `/api/highlights`；成功轻提示“已高亮”。
4. 同一页再次打开，已高亮片段恢复（若服务返回）。

### 4.5 离线/失败

| 场景 | 行为 |
| --- | --- |
| 网络失败 | 存本地队列（`chrome.storage.local`），badge 显示待重试；联网后自动重试 |
| 服务未启动 | “剪藏服务没有响应。确认服务已启动，地址是否正确。” |
| Token 无效 | “访问 Token 无效。去设置里更新。” |
| 页面不允许 | “这一页不允许抓取。试试选中正文后再剪藏。” |
| 混合内容 | “HTTPS 页面不能连接 HTTP 服务。把服务换成 HTTPS，或用本地应用剪藏。” |
| 内容过大 | “正文超过 200 KB，已截断保存。” |

## 6. 权限与隐私

| 权限 | 现状 | 建议 |
| --- | --- | --- |
| `storage` | 有 | 保留（Token/队列） |
| `activeTab` | 有 | 保留（点击时读当前页） |
| `scripting` | 有 | 保留（注入按钮/抓正文） |
| `host_permissions: <all_urls>` | 有 | 改为 `optional_host_permissions`，点击时按需申请 |
| `tabs` | 无 | 不申请 |
| `history` | 无 | 不申请 |
| `cookies` | 无 | 不申请 |

- Token 存 `chrome.storage.local`，不同步到云端；选项页可清除。
- 不上报分析数据；不加载远程脚本；CSP 默认。
- 剪藏内容只发送到用户配置的服务；首次使用明确告知。
- 权限被拒：功能降级（仅手动复制），给开启指引。

## 7. 三端与全触点差异

| 触点 | 差异 |
| --- | --- |
| Chrome/Edge | 完整功能；sidePanel 可用 |
| Firefox | MV3 兼容；`browser.*`；sidePanel 不支持 |
| Safari | 不提供（需另行打包） |
| 安卓 | 无扩展；用分享 Sheet 把链接发给观复 |
| 主应用 | 收集箱显示来源/原文/标签；与扩展同 token |
| 官网 | 下载/安装说明；隐私说明 |

## 8. 落地映射

- `extension/manifest.json`：`action.default_popup` 320；`optional_host_permissions`；`side_panel`（可选）。
- `popup.html`：320 宽；CSS 变量与主应用同源（复制 token）；字体 13/14。
- `content.js`：Shadow DOM；注入按钮/工具条；`locator.js` 负责正文选择器。
- 队列：`chrome.storage.local` `gf-clip-queue`；`chrome.alarms` 每 1 分钟重试。
- 图标：16/32/48/128；品牌标（见 26）。
- 测试：Playwright 加载扩展；对 `example.com` 剪藏；断网重试；权限拒绝。

## 11. 开发前先做 HTML 预览稿

**在按本文件开发之前，必须先做 HTML 预览稿给用户判断。** popup 只有 320 宽，标题多一行、按钮高 4px、状态文案长一句，就会显得挤；注入按钮是“圆形图标”还是“展开胶囊”，在真实网页上感受完全不同。预览稿要把 popup 的 6 个状态、注入按钮的 3 种形态、划词工具条、选项页并排展示，并模拟深浅色网页背景，用户确认后再改源码。
