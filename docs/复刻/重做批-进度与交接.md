## 四、环境与踩过的坑（直接复用，别重踩）

- **改文件**：优先 `Edit`/`Write`；在 Bash 里用 `node -e` 做替换时**禁止模板字符串**（`${}` 会被 shell 吃掉）——改用行号手术或先 Write 一个 patch 脚本再 `node tools/patch-xxx.mjs`。
- **UI 点验**：全部是 `app/tools/*-check.mjs` + `npm run xxx-check`（playwright-core 复用本机 Chrome，无需下载浏览器）；截图落 `docs/验收证据/重做批/W-xx/`。
  现有脚本：`theme-shot` `tabbar-check` `tab-size-check` `nav-check` `tabctx-check` `tab-isolation-check` `tab-more-check` `tab-boundary-check` `win-final-check` `sidebar-check` `iconrow-check` `tree-row-check` `rowctx-check` `rowmore-check` `newchild-check` `trashbar-check` `notif-check` `pageref-check` `sidebar-toggle-check` `toolbar-check` `pagehead-check` `iconpicker-check` `cover-check` `pageheadbar-check` `mention-check` `pagemenu-check` `narrow-check` `blocks-check` `media-check` `pageblock-check` `blockmenu-check` `convertpanel-check` `drag-check` `fields61-check` `advfields-check` `grid-check` `cell-semantics-check` `cell-editor-check` `colmenu-check` `colright-check`。
- **dev server**：`cd app && npm run dev`（5173）。测试/构建：`npm test`、`npm run build`、`npm run check`。
- **记录编辑入口**：点击表格行会打开「记录详情」；**双击单元格**才进入就地编辑——写自动化脚本时注意，别把“行打开”误判成编辑失败。
- **表格 DOM**：行首有行号 TD，字段 i 对应 `td[i+1]`；滚动容器是 `.collection__scroll`；表头按钮 `.grid__th-btn`，列菜单 `.col-menu`。
- **CSS 优先级**：表格 `th/td` 的尺寸规则 specificity 高，改单元格态要写 `td.grid__cell--xxx` 这种组合选择器。
- **颜色一律走令牌**（2026-11-19 起）：新增 UI 代码写死颜色会被 `npm run check` 的令牌守卫拦下。
  尺寸类数值同理——没有对应令牌就先去 `app/src/styles/tokens.css` 补一个。
- **做视觉零变化验证**：`npm run token-verify-shot`（浅/深两张图 + 34 个探测点计算样式）配
  `node tools/png-diff.mjs A.png B.png`（零依赖 PNG 像素差分）。
  **注意**：页面里的「创建/最后修改」时间戳每次运行都变，直接比图会有几百个假差异像素——
  `token-verify-shot.mjs` 已内置时间戳遮罩；改动后建议都跑一次确认差异为 0。
- **测试偶发**：`npm test` 与 `prebuild`（gen-icons）并发时偶尔读到少文件，单独重跑即可；连续两次全绿才算数。
