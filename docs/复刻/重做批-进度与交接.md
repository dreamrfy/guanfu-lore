## 四、环境与踩过的坑（直接复用，别重踩）

- **改文件**：优先 `Edit`/`Write`；在 Bash 里用 `node -e` 做替换时**禁止模板字符串**（`${}` 会被 shell 展开）。
- **UI 点验**：全部是 `app/tools/*-check.mjs` + `npm run xxx-check`（playwright-core），必须真实浏览器跑，不许只看 DOM 静态结果。
- **dev server**：`cd app && npm run dev`（5173）。测试/构建：`npm test`、`npm run build`。
- **记录编辑入口**：点击表格行会打开「记录详情」；**双击单元格**才进入就地编辑——写自动化脚本时注意，别把“行打开”误判成编辑失败。
- **表格 DOM**：行首有行号 TD，字段 i 对应 `td[i+1]`；滚动容器 `.collection__scroll`；表头按钮 `.grid__head` 系列。
- **CSS 优先级**：表格 `th/td` 的尺寸规则 specificity 高，改单元格态要写 `td.grid__cell--xxx` 这种组合。
- **颜色一律走令牌**（2026-11-19 起）：新增 UI 写死颜色会被 `npm run check` 的令牌守卫拦下。
- **视觉零变化验证**：`npm run token-verify-shot`（浅/深两图 + 34 个探测点）配 `png-diff`。
- **测试偶发**：`npm test` 与 `prebuild`（gen-icons）并发时偶尔读到少文件，单独重跑；连续两次全绿才算数。
- **红线**：FlowUs 截图只放 `ops/观测/`，不进仓库；`docs/复刻/14`–`27` 为专项成果，只读不随意改数值；`docs/基准/`、`docs/归档/`、`requirements-v1/` 不改。
