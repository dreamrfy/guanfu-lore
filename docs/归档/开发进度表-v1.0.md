## 0 这张表怎么用

- **"人天"口径**：1 人天 = 6 小时有效工作，已包含写代码、自测、修 bug 和留验收证据的时间，**不含需求变更导致的返工**。
- **状态列**：`未开始` / `进行中` / `待验收` / `已验收` / `阻塞`。每次更新只改状态和备注，不改已确认的范围。
- **本表不写死日历日期**：你还没定开发人和启动日。等 M0 启动日确定后，可按第 3 节的换算把它排成具体周次。
- **30 元/月是运行费**（云存储、流量、AI），不是开发人力成本；两笔账分开算，人力口径见第 7 节。
- **顺序依据**：需求文档第 19.2 节的建议分批（基础内容模型与离线可靠性 → 资料库与视图 → 剪藏存档 → AI 及成本 → 跨端与导出恢复），但把最高风险的微信链路与云服务验证**提到最前面**，避免大量开发后才发现核心入口不成立。

## 4 每个阶段的"完成才算完"

所有阶段共用以下判定，缺一项都不算完成：

- 表中对应需求编号逐条有可演示行为，不是假菜单占位。
- 对应验收场景在**真实设备、真实网络、允许的来源**上跑过，并留下截图/录屏/日志证据。
- 断网、失败、空间不足、权限错误至少各测一次；**不假报保存成功、不假报存档完整**。
- 数据库结构变更带迁移与回滚；升级不清数据。
- 手机端关键操作不依赖悬停/长按/拖动，触控目标不小于 44 逻辑像素。

| 阶段 | 必须证明的一件事 |
| --- | --- |
| 0 | 微信链路要么有真机证据，要么明确写"不成立"并给出替代方案 |
| 1 | 强制断网写笔记，杀进程重开内容仍在；写盘失败时不显示"已保存" |
| 2 | 一篇含图片、代码、勾选的笔记能导出 Markdown 再导回，损失项有说明 |
| 3 | 同一批记录在六视图间改一处处处一致；删视图不删记录；隐藏列不丢值 |
| 4 | 改名并移动目标页面后，反向引用仍能点回原文位置 |
| 5 | 真正断开原站访问后，已存档正文与全部必需图片仍可读；重复转发不产生重复记录 |
| 6 | 多任务并发时先预留预算；未知费率不当零放行；AI 失败只重试 AI |
| 7 | 两台设备离线改同一篇，双方内容都在；提交合并时能再发现云端新修改 |
| 8 | 断网搜索明确告诉用户哪些正文没索引到，不写成"知识库没这条" |
| 9 | 折叠分支不删节点；删除分支提示节点数且可撤销；导图离线可编辑 |
| 10 | 另一台未登录设备断网打开导出的 HTML，图片样式完整、无外部请求 |
| 11 | 备份包在独立恢复集里还原出页面身份、属性、视图与引用，并核对附件 |
| 12 | 非本人无法读取私有对象；密钥不出现在导出包和普通日志里 |

## 6 开工前需要你确认的 6 件事

1. **微信验证失败时的处理**：换入口、换目标（例如改用邮件/网页收藏夹作为主入口）、还是暂停项目？
2. **云服务方向与预算弹性**：30 元/月是目标，若测算结果明显超出（例如需要固定服务器），上限放到多少？
3. **谁来做、投入节奏**：你自己做、找人做，还是两者结合？这直接决定第 3 节用哪一行。
4. **是否接受"先 M1 自用、再 M2–M4"的分批交付**。
5. **同步基线的取舍**：冲突时默认"保留两页"还是"进冲突页手动合并"？两者工作量不同。
6. **人力预算口径**：第 7 节的单价怎么填。
