# 复刻基准与约束 v1（2026-11-16 用户拍板）

> 这份文件是**给以后每个会话看的护栏**：做观复前端时先读它，不要凭自己的理解发挥。
> 所有条目都是 2026-11-16 与用户逐条确认过的，未确认的一律不许自作主张。

## 一、我们到底在对标什么

- **对标产品**：FlowUs（息流）。观复三端＝**学它的前端表现与交互逻辑**，不是复制它的代码。
- **不复制代码、不换栈**：Web/桌面继续 React + BlockNote；安卓继续 Kotlin + Compose；数据层/同步层沿用我们自己的实现（Dexie/Room、自建同步协议）。规格里只写"在我们栈里怎么落地"。
- **Notion 的位置**：只在两个专项里出场（颜色美化、文案对比），不作为实现基准。
- **三端一致**：交互逻辑三端一体；界面各自贴合 FlowUs 对应端（手机端允许必要的移动化适配，但不能变成"另一个样子"）。

## 二、保真度

| 维度 | 结论 |
| --- | --- |
| 布局/间距/圆角/尺寸/层级 | **像素级对齐**，观测时量尺寸 |
| 图标、字体 | **允许不同**（换我们自己的） |
| 颜色 | 先**记录**；之后做「FlowUs / Notion / 观复品牌色」对比专项再定 |
| 文案 | 先**照录**；之后做同样的三方对比专项再定 |
| 深色主题 | **两套都要对齐**（深色下描边/反色/斑马纹都不同） |

## 三、范围

- **不做**：团队空间 / 协作 / 模板市场 / FlowUs 的商业化界面（套餐、空间容量、升级）。
- 商业化界面腾出的槽位（左下角容量卡、头像菜单、设置里的套餐页）→ **用观复独有功能原位替换**（收集箱与剪藏入口、AI 供应商设置、同步与凭证）。
- 观复独有、FlowUs 没有的功能（微信剪藏、企业微信接收、AI 供应商）：**单独设计一版交用户拍板**，不进 95% 对照表。

## 四、流程与验收

1. 先交《复现规格》（**先交一个模块样本**，用户认可格式与粒度后一批一模块推进）。
2. 规格 → 两个专项（颜色、文案）+ 独有功能设计稿 → 重做。
3. **重做顺序：Web + 桌面先行（同一套代码），安卓跟齐。**
4. 重做验收线：**界面逐屏并排对照通过 + 功能真能用**（新建/编辑/保存/同步/搜索/回收站）。
5. 模块清单（一批一模块）：导航外壳与多页签 → 首页/最近 → 页面树 → 页面/编辑器与块类型 → 多维表与全部视图 → 搜索 → 收集箱与剪藏 → AI → 设置与账号 → 分享与公开只读页。

## 五、观测与证据纪律

- 三端取证：安卓 `adb screencap` + `uiautomator dump`；网页 Tabbit CLI（Playwright + DOM/`getComputedStyle`）；Windows 客户端 `PrintWindow` 截图（需要时用调试参数重启读 DOM）。
- **FlowUs 界面截图/控件树/录屏只留本地**（`ops/观测/`），**不进公开仓库**；仓库只放我们自己写的文字规格。
- 用户真实账号：可自由新建/修改/删除内容；**账号密码类页面不抓、不留**；已抓到的含密钥/个人资料的页面**即时删除**。
- 手机为深色主题；浅色对照需要切主题后各抓一遍。

## 六、已知的"最容易做错"清单（写在这里防复发）

1. 把桌面的**常驻侧栏**照搬到手机（手机是抽屉）。
2. 把桌面的**段首浮动工具条**照搬到手机（手机是"贴键盘的工具条"）。
3. 把桌面的**块左侧悬浮菜单**照搬到手机（手机是底部动作面板）。
4. 把 `/` 菜单在手机上也做成纵向列表（手机是两列网格 + 搜索）。
5. 忘记手机底部固定栏五项（☰ / 搜索 / 新建页面 / AI / 偏好设置）。
6. 忘记分组结构是「空间页面 / 个人页面」两级，而不是一锅平铺。
