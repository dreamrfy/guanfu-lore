# V3.3 开源候选手册

> 与《V3.3 需求清单与部件树》**同一套编号一一对应**（M1-01、M3-22…）。
> 需求清单保持「要什么」，本手册记录「去哪里拿现成的」。
>
> **每个候选记录四件事**：授权 / 活跃度 / 能力边界（有什么、缺什么）/ 集成方式与工作量。
> **没选中的候选也留档**——将来别的功能可能用得上。
> 建档 2026-11-12 ｜ 逐模块推进中

### 核实标记

| 标记 | 含义 |
| --- | --- |
| ✅ | 已打开仓库/官方页核实（授权、活跃度、能力） |
| ⚠️ | 仅来自搜索摘要或多方二手信息，**用前需复核** |
| ❓ | 还没查到，待查 |

### 授权标记（按用户 2026-11-12 定的口径）

| 标记 | 含义 |
| --- | --- |
| 🟢 宽松 | MIT / Apache-2.0 / BSD / ISC——代码可自由拿去用 |
| 🟡 弱传染 | MPL-2.0 / LGPL——改动它的文件要开源，自己项目可闭源 |
| 🔴 强传染 | GPL / AGPL——**一旦并入产品，整个产品必须开源**，否则侵权 |
| ⚫ 商业 | 需付费授权 |

| **Milkdown** | ProseMirror + remark | 🟢 **MIT** | ✅ 活跃 | Markdown 优先的所见即所得；**一切皆插件**的架构（与你思路最合）；灵感来自 Typora | 块级 Notion 式 UI 要自己搭 | npm | 中 |
| **Editor.js** | 原生 JS，块式 | 🟢 **Apache-2.0** | ✅ 活跃（v3 开发中，v2 每季度大版本） | 干净的块式 JSON 结构；块类型靠插件扩展 | Notion 式行内体验较弱（偏"积木"） | npm | 中 |
| **Lexical** | Meta 出品，React | 🟢 **MIT** | ✅ 活跃 | 性能与无障碍做得好；模块化 | **生态偏底层**，Notion 式块编辑器要自己搭很多 | npm | 中→高 |
| **Plate** | Slate 系 | ⚠️ 待复核（普遍标 MIT） | ⚠️ | 组件化，插件多 | 同上 | npm | 中 |
| **appflowy_editor** | **Flutter / Dart** | 🔴 **AGPL-3.0 双授权**（⚠️ **重大发现**） | ✅ 活跃 | Flutter 生态里最完整的块编辑器；有工具栏/斜杠等 | **AGPL 传染**：用它做产品，产品须开源（除非买商业授权）；Flutter 生态缺多维表/白板等配套 | pub 依赖 | 中 |

### 这张表的直接结论

1. **若客户端走 Web 技术栈**（React/Tauri/Electron）：**BlockNote 是"最省力"的选择**——
   斜杠菜单、拖拽手柄、块菜单这些你在 FlowUs 里最顺手的交互它开箱就有；缺点是没多维表（模块二另找）。
2. **BlockSuite 是"能力最全"的选择**：它连白板（M6-07）都自带，AFFiNE 用它做出了完整的数据库视图。
   代价是需要自己组装 UI。
3. **appflowy_editor 的 AGPL 是个必须注意的事实**：它不是"可以随便拿"的宽松授权。
   按你定的口径（候选不设限、但授权必须标清）它可以用，但要清楚**代价是整个产品得开源**。
4. **Tiptap 是"自由度最高"的选择**：MIT、生态最大，但无头——**你在 FlowUs 里顺手的那套交互要自己写**，
   这恰恰是最费工的部分。

## 本模块小结

- **只要编辑器内核选对（BlockNote / BlockSuite），M1-07~M1-28 里一大半是"零成本自带"**；
  反过来若选无头内核（Tiptap/Lexical），这些全都要自己写——**这就是"选件决定工作量"的典型**。
- **真正没有现成开源件、必须自己写的只有三处**：侧栏页面树（M1-02/03，有通用树组件但无完整方案）、
  反向链接索引（M1-33）、版本历史（M1-31）。**其余都能拿现成的。**
- ⚠️ **两条待复核**：Plate 的授权、Tiptap 生态里拖拽手柄的免费替代包。
- 🔴 **AGPL 风险点已锁定**：`appflowy_editor`。若用它，产品须开源（或买商业授权）。

# 模块二：多维表格（M2-01 ~ M2-32）

## 先说一个关键判断：这里有两种完全不同的拿法

**路线甲：把开源"表格产品"当表后端用**（Baserow / Grist / Teable / NocoDB / APITable）
——它们本身是**完整应用**（自带界面、账号、API），能 Docker 部署到你 VPS，通过 API 读写。
- 优点：字段类型、筛选、排序、视图、权限全是现成的，省掉的活最多
- 缺点：**不是"组件"**——塞不进你的界面。要么 iframe 嵌（界面割裂、丑），要么只当后端、表格 UI 还得自己写
- 适用：如果你愿意接受"表格就用它那个界面"

**路线乙：自建数据层 + 开源 UI 组件拼表格**
- 数据层：自己在 SQLite/Postgres 里存「表 / 字段 / 记录 / 视图配置」
- UI 层：开源表格组件（TanStack Table 等）+ 字段小组件拼
- 优点：**表格能长得跟 FlowUs 一样**（这正是你的核心要求），交互完全可控
- 缺点：字段类型、筛选、排序的逻辑得自己实现（都是常规工程活，不难）

**中间选项：BlockSuite 的 database**（AFFiNE 的表格能力，MPL-2.0，**可嵌入**）
——目前唯一"开源 + 可嵌入 + 已做出完整多维表"的东西，代价是要用它整套技术栈。

## 本模块小结

- **若走 Web 栈，推荐路线乙**（自建数据层 + TanStack Table 无头逻辑 + 各字段小组件）：
  唯一能同时满足"长得像 FlowUs"和"可嵌入"的路。完整产品（Baserow/Grist）只能当后端或 iframe，**交互会割裂**。
- **本模块没有"难找的开源件"**：字段类型、筛选、排序、导入都有现成库或内置能力兜底；
  真正要自己写的只有**数据模型**和**改类型不丢数据**这类业务逻辑。
- ⚠️ **三个授权雷区**：NocoDB（已非标准开源）、HyperFormula（GPL/商业）、Handsontable（商用收费）。
- 🔴 **AGPL 项**：APITable、Formbricks/HeyForm 类表单工具。

## 本模块小结

- **采集类几乎全是"部署现成件"**：RSSHub（万能订阅）、wechat-article-exporter（公众号批量）、

- 🔴 **AGPL 集中区**：Karakeep、Linkwarden、SingleFile（⚠️）。这几件如果要**把代码并进产品**须谨慎；
  但**部署成独立服务、通过网络调用**是常见且可行的用法（这条边界要在决策时明确）。
- ⭐ **两个"高价值发现"**：**RSSHub**（一条路解决多平台采集）和 **Karakeep**（与你的剪藏库形态几乎一致的完整参考）。
- **唯一必须自研的入口**：M3-01 企业微信转发通道——因为这是你特有的业务通道，开源界没有等价物。
- ⚠️ **两点待复核**：Obsidian Web Clipper 的授权、SingleFile/monolith 的授权。

- ⚠️ **新踩到的三个授权坑**：**Typesense（GPL-3.0）**、**tldraw（生产要授权）**、
  **Pandoc（GPL-2.0，只能当独立工具调用、不能并入产品）**。
- ⭐ **三个"一举多得"的发现**：
  - **Iconify**：一套接口聚合 20 万+ 图标，你"图标可切换"的需求直接落地；
  - **Meilisearch**：同时解决全文检索和混合检索（和模块四的语义搜索合流）；
  - **Tauri 2**：桌面端体积/内存远优于 Electron，**且原生支持手机端**——对"三端"目标很关键。
- **本组里真正要自己写的**：引用条三计数（M5-08）、反向链接索引（M5-07）、
  FlowUs 数据导入器（M7-07）、标签与主页这类"业务组合"。

# 全书结论

## 一、必须自研的清单（全 222 条里只有这些）

| 自研项 | 为什么没有现成件 |
| --- | --- |
| **M3-01 企业微信转发通道** | 你特有的业务通道，开源界无等价物 |
| **M1-33 / M5-07 / M5-08 反向链接与引用条** | 各家笔记各写各的，无通用库 |
| **M1-31 版本历史** | 免费开箱方案缺（付费的有） |
| **M2-01 / M2-05 多维表数据模型与"改类型不丢数据"** | 完整产品不开放成组件，逻辑要自己实现 |
| **M3-30 收集箱 / 未读队列** | 你的产品差异点 |
| **M7-07 从 FlowUs 搬数据** | 只有你知道要搬什么（**已采的基准规格是最大资产**） |
| 各处**业务组合**（标签、主页、模板、记录页、侧栏树） | 都是"用现成组件拼业务"，不是造底层 |

> 除这些之外，**其余全都有成熟开源件**。

| 路线 | 编辑器 | 桌面/网页/手机 | 表格 | 同步 | 适合谁 |
