| 本地实现（现在） | 云上（阶段一） | 改动量 |

| `src/store/localStore.ts`（node:sqlite） | **CloudBase 数据库**（文档型） | ✅ **代码已就绪**（2026-11-05，`store/cloudbaseStore.ts` + 15 项自测；SDK 随云函数打包时装，集合在控制台建） |
| `src/store/localStore.ts` writeAssetFile（本地落盘） | **R2 对象存储**（provider=`r2`） | ✅ **代码已就绪**（2026-11-05，`store/r2Store.ts`，S3 SigV4 只用 Node 内置 crypto，18 项自测；桶与凭证待在 Cloudflare 创建/注入） |
| `KF_SECRETS_FILE`（仓库外 JSON 文件） | 云函数**环境变量直接给值** | ✅ **已实现**（2026-11-05，§4；config.selftest 13 项断言） |

但**凭证读取方式必须改**：本机是「环境变量给路径 → 读仓库外 JSON」，云上通常没有文件系统，应改成「环境变量直接给值」。

## 3 图片/快照存储：本地落盘 → R2

| 项 | 内容 |
| --- | --- |
| 本地 | `writeAssetFile/readAssetFile`（provider=`local`，落 `data/assets/`） |
| 云上 | **R2**（provider=`r2`）：S3 兼容签名（HMAC，无需 SDK，~100 行） |
| 读取 | App 端由服务端按 `assetId + provider` 生成**带签名的临时 URL**（私有桶）或直链（公开桶） |
| 改动量 | 新增 `store/r2Store.ts` ≈100 行 |

**凭证**（环境变量注入，**不进仓库**）：`R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET`。

**好处（实测数据）**：R2 出流量免费 → App 看图的流量费 = 0；免费 10GB ≈ 5,000 篇剪藏。

## 4 凭证注入（需要改代码，不是 0 行）

| 键 | 本地 | 云上 | 现状 |
| --- | --- | --- | --- |
| `KF_SECRETS_FILE` | 仓库外 JSON 文件的**路径** | 云函数没有持久文件系统 | ✅ **已改**（2026-11-05）：`config.ts` 新增环境变量直读（五项 `KF_CORP_ID`/`KF_AGENT_ID`/`KF_APP_SECRET`/`KF_TOKEN`/`KF_ENCODING_AES_KEY`，任一存在即走此分支，缺项报错点名；本地文件读法保留为回退），config.selftest 13 项断言 |
| `KF_FETCH_TOOL` | 仓库外抓取脚本路径 | 云上不需要（抓取已在 `src/fetch/`） | 已废弃，可删 |

**改动量：约 20 行**（`config.ts` 增加 `loadSecretsFromEnv()`，优先环境变量、回退文件）。
原文档写「0 行（config.ts 已按环境变量设计）」**与实现不符**：`config.ts` 读的是文件路径，不是直接读值。

## 5 抓取代码（现状：**已在仓库内**）

**现状（2026-11-04 整改后）**：抓取实现已在 `server/src/fetch/`（`http.ts` / `article.ts` / `images.ts`），
不再依赖仓库外脚本。原因：审计 P1-01 要求「消息 → 解析 → 抓取 → 图片 → 状态 → 落库」可复现，
把关键链路的抓取放在仓库外会导致报告无法验证。

安全措施（对应审计 P0-01 / P1-06）：

| 措施 | 实现位置 |
| --- | --- |
| 只允许 http/https，拒绝内嵌用户名口令 | `fetch/http.ts parseTarget` |
| 地址判定用 `net.BlockList`，IPv6 fail-closed（只放行 2000::/3） | `fetch/http.ts isBlockedAddress` |
| DNS 解析结果校验并钉住（防 rebinding） | `fetch/http.ts safeLookup` |
| 重定向逐跳复检，最多 5 跳 | `fetch/http.ts safeRequest` |
| 响应体上限（正文 10MB / 图片 20MB），Content-Length 与实际字节双检 | `fetch/http.ts requestOnce` |
| 主机白名单（文章 `mp.weixin.qq.com`；图片 `mmbiz.qpic.cn` 等） | `pipeline/wire.ts`、`fetch/images.ts` |

**静态扫描说明**：若 semgrep/Mimosa 仍把「入口参数 → 网络请求」判为 SSRF，处理方式建议：
1. 在 `fetch/http.ts` 与 `pipeline/wire.ts` 加 `nosemgrep` 注解 + 评审记录（推荐，最透明）
2. 或对这两个文件配置规则排除
3. **不要**把抓取移回仓库外——那会让全链重新变得不可复现

## 7 轮询频率与 3 天窗口（运营注意）

| 项 | 说明 |
| --- | --- |
| 阶段一频率 | **每 30 分钟**（远小于 3 天窗口，不会丢消息） |
