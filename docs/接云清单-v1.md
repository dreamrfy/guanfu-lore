## 3 图片/快照存储：本地落盘 → R2

| 项 | 内容 |
| --- | --- |
| 本地 | `writeAssetFile/readAssetFile`（provider=`local`，落 `data/assets/`） |
| 云上 | **R2**（provider=`r2`）：S3 兼容签名（HMAC，无需 SDK，~100 行） |
| 读取 | App 端由服务端按 `assetId + provider` 生成**带签名的临时 URL**（私有桶）或直链（公开桶） |
| 改动量 | 新增 `store/r2Store.ts` ≈100 行 |

**凭证**（环境变量注入，**不进仓库**）：`R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET`。

**好处（实测数据）**：R2 出流量免费 → App 看图的流量费 = 0；免费 10GB ≈ 5,000 篇剪藏。

## 5 抓取代码落仓库（安全评审项 ⚠️）

**现状**：抓取实现在仓库外（`E:\dev\tmp\wecom-kf-test\fetch-article.js`），原因：semgrep 把「入口参数 → 网络请求」判为 SSRF/命令注入（域名白名单 + 参数逐个校验 + 内网拒绝 + 完整审计 0 发现 也无法通过）。

**接云时的处理（三选一，需用户确认）**：
1. **nosemgrep 注解 + 评审记录**：对抓取文件逐行加 `// nosemgrep` 注解，附评审说明（host 白名单/参数校验/内网拒绝的实现证据）→ 提交
2. **调整 semgrep 规则**：对该文件/目录加排除（`.semgrepignore` 或规则配置）
3. **保持仓库外**：抓取逻辑继续放仓库外，仓库内只留解析/存储（现状）

**推荐 1**：nosemgrep 注解 + 评审记录，最透明。
