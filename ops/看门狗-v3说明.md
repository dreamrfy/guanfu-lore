# 看门狗 · 操作说明（规则第 4 版）

> 给未来的会话看。用户说「**开始**」→ 照本文把定时任务建起来；用户说「**停**」→ 照本文停掉。

## 一张表看懂这版规则

| 项 | 规则 |
| --- | --- |
| 触发频率 | **每 10 分钟**一次（每次触发 = 一个全新会话） |
| 做完一个任务之后 | **本会话内立刻接着做下一个**，不等下一轮触发 |
| 触发时上一个任务还没做完 | **不等、不抢**：直接领一个不在 `running` 里的任务（并行） |
| 并行限制 | 并发上限 **2**；且**只允许跨模块并行**（同一模块内的相邻任务往往改同一批文件） |
| 上下文 | 一个会话做完 **2 个任务**或工具调用累计 **约 60 次**，就收尾换新会话 |
| 权限 | 插件/依赖/下载/编译/云资源**全开**；token 与费用**不设限** |
| 收工 | 没有固定时间；只有 `ops/STOP`、无可领任务、登录过期三种情况停 |

## 文件分工

| 文件 | 作用 | 谁改 |
| --- | --- | --- |
| `开发任务表-v3.0-FlowUs复刻版.md` | **任务来源**：104 个任务 + 状态列 + 执行纪律 + 采集通道 + 决策记录 | 看门狗每完成一个任务改状态 |

| `ops/锁/` | 任务认领锁 `T-<任务号>.lock` 与 `构建.lock` | 看门狗增删；正常应为空 |

## 启动

1. `CronList` → 若有标题含「FlowUs复刻看门狗」的旧任务，先 `CronDelete` 删掉。
2. 读 `ops/看门狗-v3提示词.md`，取 **「## 提示词正文（从下一行开始整段复制）」之后、到「（提示词结束）」之前**的整段文字，原样传给 `CronCreate`。
3. `CronCreate` 参数：

| 字段 | 值 |
| --- | --- |
| `title` | `FlowUs复刻看门狗（每10分钟触发，并行跨模块，做完104个任务才停）` |
| `intervalUnit` | `minute` |
| `interval` | `10` |
| `cron` | `* * * * *` |
| `recurring` | `true` |

4. 校准 `ops/运行状态-v3.json`：`runtime.startedAt` = 现在，`probeCount` 归 0，`running` 清空，`history` 保留。
5. `CronList` 核对 `nextRunAt`，回报「看门狗已启动，首次触发 HH:MM，从 <任务号> 开始」。

## 停止

- **首选**：仓库根目录建空文件 `ops/STOP`。下一次触发会看到它，补齐报告、提交、自暂停。
- **备选**：直接 `CronDelete` 掉定时任务。
- 停完记得**删掉 `ops/STOP`**，否则下次启动会立刻又停。

## 用户怎么验收

- 看 `ops/执行报告-v3.md` 里的「📦 模块 Mx 已完成 · 待用户验收」条目。
- 每个模块都有：并排对照图（`docs/基准/证据/<模块>/`）+ 可运行的 Windows 版。
- **验收不阻塞流水线**：没验收也会继续做下一个模块。

## 出问题怎么办

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 采集类任务全标 `BLOCKED·登录过期` | FlowUs 登录态 30 天到期（约 2026-12-10） | 用户配合给一次手机验证码，重跑 `probe.mjs` → `step3.mjs` → `step4.mjs` |
| `ops/锁/` 里有残留锁 | 上一个会话被中断 | 看锁文件里的时间：超过 45 分钟的可以直接删；短的等一轮 |
| 某任务反复 `SKIP·超时` | 单个任务确实做不完 | 拆成更小的任务追加到表末尾，原任务标 `DONE·部分` |
| 并发一直满 | `maxConcurrent` = 2 已经有两任务在跑 | 正常，等下一轮触发 |
