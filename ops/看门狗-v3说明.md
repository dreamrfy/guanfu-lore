# 看门狗 · 操作说明（V3）

> 给未来的会话看。用户说「**开始**」→ 照本文把定时任务建起来；用户说「**停**」→ 照本文停掉。

## 三个文件的分工（别搞混）

| 文件 | 作用 | 谁改 |
| --- | --- | --- |
| `开发任务表-v3.0-FlowUs复刻版.md` | **任务来源**。104 个任务 + 状态列 + 执行纪律 + 采集通道说明 + 已定决策 | 看门狗每完成一个任务改状态；用户/AI 可调任务 |
| `ops/运行状态-v3.json` | **调度状态唯一真相**。current / history / blocked / deferred | 只有看门狗改 |
| `ops/执行报告-v3.md` | **流水日志**。每完成一个任务追加一条 | 只有看门狗追加 |
| `ops/看门狗-v3提示词.md` | 定时任务 prompt 的**源文本** | 人改；**改完必须同步更新定时任务里的 prompt** |

## 启动（3 步）

1. `CronList` → 若有标题含「FlowUs复刻看门狗」的旧任务，先 `CronDelete` 删掉。
2. 读 `ops/看门狗-v3提示词.md`，取 **「## 提示词正文（从下一行开始整段复制）」之后、到「（提示词结束）」之前**的整段文字，原样传给 `CronCreate`。
3. `CronCreate` 参数：

| 字段 | 值 |
| --- | --- |
| `title` | `FlowUs复刻看门狗（每5分钟探测，做完104个任务才停）` |
| `intervalUnit` | `minute` |
| `interval` | `5` |
| `cron` | `* * * * *` |
| `recurring` | `true` |

4. 把 `ops/运行状态-v3.json` 的 `runtime.startedAt` 改成现在，`probeCount` 归 0，`current` 置 null。
5. `CronList` 核对 `nextRunAt`，回报「看门狗已启动，首次触发 HH:MM，从 <任务号> 开始」。

## 停止

- **首选**：在仓库根目录建一个空文件 `ops/STOP`。下一次探测会看到它，补齐报告、提交、自暂停。
- **备选**：直接 `CronDelete` 掉定时任务（看门狗也可能自己因"任务跑空"暂停）。
- 停完记得**删掉 `ops/STOP`**，否则下次启动会立刻又停。

## 用户怎么验收

- 看 `ops/执行报告-v3.md` 里的「📦 模块 Mx 已完成 · 待用户验收」条目。
- 每个模块都有：并排对照图（`docs/基准/证据/<模块>/`）+ 可运行的 Windows 版。
- **验收不阻塞流水线**：即使某个模块没验收，看门狗也会继续做下一个模块。

## 已知会卡的两种情况（不是故障）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 采集类任务全部标 `BLOCKED·登录过期` | FlowUs 登录态 30 天到期（约 2026-12-10） | 用户配合给一次手机验证码，重跑 `probe.mjs` → `step3.mjs` → `step4.mjs` |
| 连续几轮回复"进行中" | 某个任务在正常跑（例如 Flutter 构建慢） | 正常；超过 `max(estimateMin×2, 40)` 分钟会自动判超时并跳过 |
