# 看门狗 · 重建说明（给新会话用）

> **场景**：用户休息前说一句「**开始**」，由**新开的会话**照本文重建夜间看门狗。
> 之所以要新会话：上一个会话上下文接近上限（那条会话已完成本轮全部准备工作，见文末交接）。
> **重建只需 3 分钟**，照下面 5 步做，做完回报「首次触发时间」。

---

## 重建 5 步

### 第 1 步 · 清场
调用 `CronList` 确认当前工作区有没有残留的定时任务。若有（标题含"夜间看门狗"），先用 `CronDelete` 按 id 删掉，避免重复触发。

### 第 2 步 · 取提示词正文
读本仓库 `ops/看门狗提示词.md`，取出 **「## 提示词正文（从下一行开始整段复制）」之后、到「（提示词结束）」之前**的整段文字 —— 这就是要传给定时任务的 prompt。**照抄，不要改写。**

### 第 3 步 · 创建定时任务（用 CronCreate，参数照抄）

| 字段 | 值 |
| --- | --- |
| `title` | `夜间看门狗（每5分钟探测一次，08:00 收工）` |
| `intervalUnit` | `minute` |
| `interval` | `5` |
| `cron` | `* * * * *` |
| `recurring` | `true` |
| `prompt` | 第 2 步取到的那段正文 |

> 说明：`intervalUnit=minute` + `interval=5` 表示"每 5 分钟"；`cron` 只是合法展示表达式。
> 探测轮次绝大多数几秒钟就退出，成本极低——**不要**改成 30/40 分钟这种固定间隔（那会让任务做完后空等）。

### 第 4 步 · 校准运行状态
编辑 `ops/运行状态.json`：
1. `runtime.startedAt` → 改成**本次启动时间**（ISO 时间）
2. `runtime.stoppedAt` → 删掉或置 null
3. `runtime.probeCount` → 归 0，`lastProbeAt` → null
4. 若 `current` 不是 `null`（说明上一夜有任务中断）：
   - 去 `ops/夜间任务队列.md` 找到那个任务，把它的状态改回 `待执行`（并在「进度交接」栏保留上次留下的说明）
   - 然后把 `current` 置为 `null`
5. **不要动** `history` 与 `deferred`（保留历史）

### 第 5 步 · 核对进度并回报
1. 读 `ops/夜间任务队列.md` 的状态栏，统计：已完成 N 个 / 待执行 M 个（**本夜从第几个任务开始**要写清楚）
2. `CronList` 核对新任务的 `nextRunAt`，换算成本地时间
3. 回报用户一句话即可：**"看门狗已启动，首次触发 HH:MM，本夜从任务 N 开始"**
