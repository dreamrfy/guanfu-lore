# 看门狗 · 操作说明（第 5 版 · 云端批）

> 用户说「**开始**」→ 照本文把定时任务建起来；用户说「**停**」→ 建仓库根 `ops/STOP` 空文件或直接删定时任务。

## 一张表看懂这版规则

| 项 | 规则 |
| --- | --- |
| 触发频率 | **每 10 分钟**一次（每次触发 = 一个全新会话） |
| 任务来源 | `开发任务表-v3.3-云端批.md`（34 任务，T00~B03） |
| 领取制 | TODO → **DOING·领取**（带锁）→ DONE / 断掉·超时 / BLOCKED·等用户 |
| 无进展断停 | 被领任务 **超 30 分钟** → 下一次触发把它标 `断掉·超时`，领下一个 |
| 断掉重试 | **留到最后**：队列无 TODO 时，按编号从小到大逐个重开 `TODO·重试` |
| 并发 | 上限 2，且只允许跨模块并行 |
| 上下文 | 单会话做完 **3 个任务**或约 60 次工具调用就收尾；下一轮触发自然新会话（≈每 3~5 任务一换，用户兜底规则） |
| 权限 | 含 VPS 部署、真实浏览器操作、Pages 部署、**备用机真机操作**（2026-11-15 放行：adb install/启动/intent/截屏，见任务表模块 T）；不含 push/花钱/备案/微信实测 |
| 收工 | 只有 `ops/STOP`、队列清空（含断掉重试完）、CronPauseSelf 三种 |

## 文件分工

| 文件 | 作用 |
| --- | --- |
| `开发任务表-v3.3-云端批.md` | 任务来源 + 执行纪律 + 状态列（看门狗改状态） |
| `ops/运行状态-v4.json` | 调度状态唯一真相（running/history） |
| `ops/执行报告-v4.md` | 流水日志（看门狗追加，「📦」= 模块待验收） |
| `ops/锁/` | 认领锁 `T-<编号>.lock`、`构建.lock` |
| `ops/看门狗-v4提示词.md` | 定时任务 prompt 源文本（改后必须同步更新定时任务） |

## 启动

1. CronList → 删掉旧标题的看门狗定时任务（如有）。
2. 读 `ops/看门狗-v4提示词.md`「## 提示词正文」之后到「（提示词结束）」之前整段。
3. CronCreate：title=`观复云端批看门狗（每10分钟·30分钟断停·断点尾重试·34任务）`，每 10 分钟，recurring。
4. 校准 `ops/运行状态-v4.json`（startedAt=现在、running 清空）。
5. CronList 核对 nextRunAt，回报首次触发时间与起始任务号。

## 停止

- 首选：仓库根建空文件 `ops/STOP`（下次触发自停并自暂停）。停完删掉 STOP。
- 备选：直接删除定时任务。

## 与上一版（v3，FlowUs 复刻）的差异

- 不再有 FlowUs 采集通道相关任务与登录过期问题。
- 断停从 `max(估时×2, 45分钟)` 改为**固定 30 分钟**；断掉任务从「SKIP 作废」改为「**队列尾部重试**」。
- 会话长度从「2 任务」放宽到「3 任务」（仍约等于用户说的 3~5）。
- 权限新增：VPS 生产部署、真实浏览器操作（用户 11-15 明确放行）。

## 用户怎么验收

- 看 `ops/执行报告-v4.md` 的「📦」条目 + `docs/验收证据/<模块>-<任务>/`。
- 安卓模块验收需要用户：装 APK（路径在报告里）+ 微信实测两个入口。
- 验收不阻塞流水线。
