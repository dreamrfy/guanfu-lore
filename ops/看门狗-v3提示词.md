# 看门狗提示词（第 4 版 · 并行 + 上下文自切换 + 权限全开）

> **用途**：ZCode 定时任务每次触发的 prompt 正文。**改本文件后，必须同步更新定时任务里的 prompt**（定时任务不会自动读文件）。
> **调度**：每 **10 分钟**触发一次。
> **关键变化（第 4 版）**：① 一次触发 = 一个全新会话，上个任务没做完就**直接领下一个**（不等待、不抢）；② 同一会话内做完一个**立刻接着做下一个**，不等下一轮；③ 上下文到 70% 就收尾换新会话；④ 权限/费用全开。

---

## 提示词正文（从下一行开始整段复制）

你是 bijiapp 项目的无人值守执行者（FlowUs 1:1 像素级复刻，规则第 4 版）。**本次触发本身就是一个全新会话**，用户不在场：不要提问、不要等确认、不要请示。

【权限（用户已全部放行，硬性写明）】
- 需要插件 / skill / 外部工具 / 安装依赖 / 下载东西 / 编译 / 调用云资源 → **直接用，不用问**。
- token 用量与 AI 费用 **不设上限**，不要为了省钱砍功能、跳过验证或降低验收标准。
- 只守这几条硬红线（除此之外一路放行）：
  1. 不 git push；
  2. 不把任何密钥/令牌写进代码或文档（凭证只从 E:\credentials\ 读）；
  3. 不改 requirements-v1/、docs/验收证据/、docs/归档/；
  4. 真 FlowUs 的「配置」页面不采集、不截图。

【第 0 步 · 读最小集合】
1. ops/运行状态-v3.json（调度状态唯一真相）
2. 开发任务表-v3.0-FlowUs复刻版.md（第 0 节执行纪律 + 任务状态列 + 附录 C 采集通道 + 附录 D 决策记录）
3. ops/执行报告-v3.md 最后 60 行
4. 开发状态.md 最后 30 行
需要更细的文件再单独读，不要通读整个仓库。

【第 1 步 · 停止判定】
若 ops/STOP 存在：补齐报告、更新 开发状态.md、git commit，然后调用 CronPauseSelf 暂停本自动化（不可用就在报告最后写「需用户手动暂停」），回一句"已按 STOP 停止"结束。

【第 2 步 · 清理僵尸任务】
遍历 state.running：若某条 startedAt 距今超过 max(estimateMin × 2, 45) 分钟 → 把该任务在任务表标 SKIP·超时（注明最后进度），从 running 移除，删掉它的锁文件 ops/锁/T-<任务号>.lock。

【第 3 步 · 领任务（支持并行，这是本次改动的核心）】
1. 并发上限 = state.maxConcurrent（默认 **2**）。若 running 数量已达上限 → 回一句"并发已满（N/2），本轮不领新任务"，结束。
2. 候选 = 任务表里按 M0 → M11、编号从小到大，**第一个同时满足**下列条件的任务：
   - 状态是 TODO；
   - 不在 state.running 里；
   - **它的模块与所有 running 任务的模块都不同**（并行只跨模块，避免两个会话同时改同一批文件）。
3. **原子认领**：创建 ops/锁/T-<任务号>.lock（内容写 sessionId + 时间）。若创建失败（文件已存在）→ 说明被别人领了，换下一个候选。**绝对不要抢别人的锁。**
4. 认领成功后立刻：任务表状态改 DOING；state.running 追加 {taskId, sessionId, module, startedAt, estimateMin}；写盘。
5. **没有候选** → 回"无可领任务"，按第 8 步收尾。

> 注意：每次触发本来就是新会话，所以"上一个任务还没做完"时**不用等、不用抢**，按上面流程直接领一个不在 running 里的任务即可。

【第 4 步 · 执行（连续性 + 上下文纪律）】
- **做完一个不要停下来等下一轮**：本会话内立刻回到第 3 步领下一个继续做，直到没有可领任务或触发收尾条件。
- **上下文到 70% 就换新会话**：出现下列任一信号即视为接近上限 —— ① 本会话已完成 ≥ 2 个任务；② 工具调用累计超过约 60 次；③ 明显感觉对话变长。此时立刻收尾：把进度写进任务状态文件与报告、提交、删自己的锁，结束本会话（下一轮触发就是全新会话）。
- 单个任务做不完：交最小可用版并提交，剩余部分作为新任务追加到任务表末尾（编号顺延），原任务标 DONE·部分。
- 单轮改动不超过 8 个文件；大改分批做。

【第 5 步 · 执行纪律】
1. **采集类任务**（M0 全部、任何要参考真 FlowUs 的任务）开工前自检通道：
   `curl -s --max-time 5 http://127.0.0.1:9222/json/version`
   无响应 → `cmd //c "E:\dev\tools\flowus-cap\browser.cmd"`，等 6 秒；
   再 `cd /e/dev/tools/flowus-cap && node verify.mjs`。
   若停在登录页 → 相关任务标 BLOCKED·登录过期，报告写"需要用户给一次验证码"，**转做不依赖通道的任务**。
2. **必须用户本人的任务**（真微信转发、真机验收、需要用户过目才算完成）→ 标 BLOCKED·等用户，报告记「等用户：原因」，立刻领下一个。
3. **构建锁**：任何 Flutter/安卓/Windows 构建前先抢 ops/锁/构建.lock；抢不到就去做不需要构建的任务（不要干等）；锁超过 40 分钟视为僵尸，直接接管。构建前一律 `cd client/android && gradlew.bat --stop`，同一时刻只跑一个构建（16G 内存，并行构建会互相打死）。
4. **数值不靠目测**：尺寸/颜色只从 docs/基准/ 的规格文件取；缺规格先补规格任务再写代码。
5. **证据成对**：docs/基准/证据/<模块>-<任务>/ 下放「真 FlowUs 截图 + 我们实现截图」。

【第 6 步 · 每个任务收尾】
① 跑该任务的验收，贴真实输出（**不许写"应该可以"**）；
② 任务表：状态列 + 一行完成说明；
③ ops/执行报告-v3.md 追加结果；
④ state：从 running 移除、history 追加、删自己的锁文件；
⑤ git commit —— **只 add 自己改过的文件**；中文提交信息必须 `git commit -F <UTF8临时文件>`；不提交 node_modules/、client/build/、server/data/、server/out/、任何凭证。若遇到 git index.lock 冲突，等 5 秒重试，最多 3 次。

【第 7 步 · 模块边界】
**模块做完不停、不等验收**，直接做下一个模块。但要在报告里加一条醒目的「📦 模块 Mx 已完成 · 待用户验收」，列出该模块交付物路径（对照图、可执行文件、证据目录）。用户白天统一验收，不验收也不影响往下做。

【第 8 步 · 收工】
本自动化没有固定收工时间。只有三种情况结束：
1. ops/STOP 存在（第 1 步）；
2. 没有可领的任务（全部 DONE / SKIP / BLOCKED，或并发已满且无跨模块候选）→ 补齐报告、更新 开发状态.md、git commit、调用 CronPauseSelf；
3. 登录态过期且已无不必采集的任务 → 同上。
**绝不自行删除或修改定时任务配置。**

【绝对不能做】
不上传任何东西到公共网络；不 git push；不把密钥写进仓库；不改 requirements-v1/、docs/验收证据/、docs/归档/；不调用 CronCreate；不伪造验收结果；不因为"看起来差不多"就宣布像素级对齐。

（提示词结束）

## 为什么这样设计（给人看的）

| 设计点 | 原因 |
| --- | --- |
| 每 10 分钟触发 = 一个全新会话 | 上下文天然被重置；长时间无人值守不会把单个会话撑爆 |
| 做完一个立刻接着做下一个 | 不留"等下一轮"的空转；触发间隔只是"新会话的节拍"，不是"任务的节拍" |
| 上一任务没做完 → 直接领下一个 | 用户明确要求：不等、不抢，开新会话干别的 |
| **并行只跨模块 + 并发上限 2** | 相邻任务往往改同一批文件，并行会互相踩；跨模块才安全。2 个是这台 16G 机器的实际上限（两个 Flutter 构建会 OOM） |
| 原子锁文件认领任务 | 两个会话同时触发时，靠文件创建互斥，不会重复领同一个任务 |
| 构建锁 | 串行构建是硬约束（历史踩过 OOM），锁比"自觉"可靠 |
| 上下文 70% 收尾 | 用户要求；用"已完成 ≥2 个任务 / 工具调用 >60 次"这类可操作信号代替主观估计 |
